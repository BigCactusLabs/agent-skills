## When to revisit

Revisit when collecting and routing background results becomes a real bottleneck, or a persistent SDK-controlled Astra session needs automatic updates from reviewers, test runners, or other agents. `ExternalMessage` could supply that input path and reduce custom result-stream handling.

## What it provides

The Python SDK's `ExternalMessage` sends external content through `turn/start.toolOutput`, preserving tool-level authority below user and developer instructions. It starts a turn when idle or joins an active regular turn. Joining handles can independently collect the shared result. Claude remains review-only; Astra owns decisions and integration.

The sender name and namespace are labels, not authenticated identities. The bridge would still need task/revision/generation matching, message deduplication, reviewed-snapshot checks, and explicit handling of failed or stale reports. Keep large reports in artifacts with short summaries because tool output can be truncated.

## Availability at the last check

- Installed CLI `0.154.0` exposes `toolOutput` (nullable `TurnToolOutput`) on v2 `TurnStartParams` in `codex app-server generate-json-schema` output (re-verified 2026-09-11); the SDK wrapper's `MINIMUM_RUNTIME_VERSION` is `0.151.0`.
- Published `openai-codex` is `0.154.0` (PyPI, 2026-09-10), pinned to `openai-codex-cli-bin==0.154.0`, and its wheel contains `ExternalMessage` (`openai_codex/_inputs.py`, accepted as `RunInput` by `turn()` and `run()`; `tool_name` must be non-empty). Earlier note: `0.147.0` lacked it; the wrapper landed in source with PR #44086 on September 9.
- **End-to-end probe, 2026-09-11 (scratchpad venv, wheel installed with `--no-deps` plus `pydantic`/`packaging`, `CodexConfig(codex_bin=~/.local/bin/codex)` so the bundled CLI package was not downloaded; one ephemeral `gpt-5.6-luna` thread, `read-only`, `deny_all`, three turns; thread total 99.3k input tokens (70.7k cached) and 0.8k output, of which 0.7k reasoning):**
  - `thread.run(ExternalMessage(...))` on an idle thread starts a turn. The content arrives as a `functionCallOutput` item with the given `name` and `namespace` (no `userMessage`), and the model described it as tool output, addressing it as `orchestrator.claude_review`.
  - `thread.turn(ExternalMessage(...))` while a regular turn is active **joins** it: the returned handle carries the same turn id, the item lands mid-turn after the model's first answer, the model emits a second `agentMessage` in the same turn, and both handles' `run()` return the same `TurnResult`.
  - `TurnResult.final_response` is only the last `agentMessage`; a joined turn's earlier answer is a separate item. Read `items`, not `final_response`, when a turn may have been joined.
  - `thread.read(include_turns=True)` fails on ephemeral threads (`-32600: ephemeral threads do not support includeTurns`); use a persisted thread if the bridge needs turn history.
  - The SDK is not installed in the default local Python environment; the probe venv lives in this session's scratchpad only.
- **Lead-under-SDK checks, 2026-09-11 (four more luna/astra turns, ~100k input tokens):** `gpt-6-astra` in an SDK-started thread sees the full `collaboration` namespace (`spawn_agent`, `send_message`, `followup_task`, `interrupt_agent`, `list_agents`, `wait_agent`) plus `request_user_input`; `model/list` declares `multiAgentVersion` v2 for astra, sol, and terra and v1 for luna, which only gets `multi_agent_v1__*` tools (`spawn_agent`, `send_input`, `wait_agent`, `resume_agent`, `close_agent`), so this skill's native-agent rules hold for an SDK-hosted Astra lead but not for a luna lead. A persisted (non-ephemeral) thread supports `thread/read` with turns. The 0.154.0 SDK answers only command and file-change approval requests; it has no handler for dynamic tools or `request_user_input`, so an adapter must keep Astra from calling `request_user_input` or answer it over raw JSON-RPC.
- Normal SDK startup launches its own app-server process (measured under 0.3 s). Connecting to an existing desktop conversation is still a separate integration to verify; this feature does not add missing native child messaging tools or restore Claude session persistence.

## Research 2026-09-11 (two luna `max` web-research legs, reports in the session scratchpad under `research/artifacts/RES-VALIDATE.r1.last.md` and `RES-PRIORART.r1.last.md`)

Design constraints confirmed from primary sources: `toolOutput` cannot be combined with user input in one turn ([app-server protocol](https://learn.chatgpt.com/docs/app-server)); a handle that joins an active turn receives events only from its attachment point, so its result can be partial ([0.154.0 API reference](https://raw.githubusercontent.com/openai/codex/refs/tags/python-v0.154.0/sdk/python/docs/api-reference.md)); truncation follows `tool_output_token_limit`, with no ExternalMessage-specific limit; the SDK supplies no event id, dedup, or cross-producer ordering; neither official SDK exposes dynamic tools or `requestUserInput` answering ([issue #42219](https://github.com/openai/codex/issues/42219) open); queued input to a persisted but unloaded thread can sit until something resumes it ([issue #44491](https://github.com/openai/codex/issues/44491)); the official example injects a deployment notification into a user-authorized task under a read-only sandbox ([example 16](https://raw.githubusercontent.com/openai/codex/refs/tags/python-v0.154.0/sdk/python/examples/16_external_message/async.py)).

Prior art: [OpenAI Symphony](https://github.com/openai/symphony/blob/main/SPEC.md) (external scheduler with attempt counters, stalls, Human Review state), [Temporal's agent framework](https://go.temporal.io/platform-hub/ai-engineering/ai-agent-framework) (durable step budget and approval signals outside the model), and Anthropic's script-owned dynamic workflows are the closest systems; none binds results to a reviewed commit SHA or has a second-rejection human gate. Supporting evidence: an external observer intervening on live trajectories cut tool failures and tokens in an A/B ([Wink](https://arxiv.org/abs/2602.17037)); 207 of 216 invalidating cases still committed after their authorizing evidence went stale, arguing for a fail-closed snapshot check ([arXiv 2607.10487](https://arxiv.org/abs/2607.10487)); a fourth review round still improved resolve rates in one study ([SWE-Review](https://arxiv.org/abs/2607.06065)), so the three-send-back cap is policy, not an optimum. Strongest objection: the adapter counts events but cannot judge semantic progress, and a bare SHA match wrongly rejects rebased or amended work; pair SHA with task, worker, generation, and ordering.

Recheck runtime compatibility and the intended session connection before adopting a changed SDK/CLI pair. The parent-controlled adapter scope is: accept a commissioned review, validate its envelope and snapshot, deliver its findings as evidence, and let Astra decide the next action.
