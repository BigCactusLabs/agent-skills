## OpenAI pricing detail (GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna)

**GPT-6.1 Sol** (`gpt-6.1-sol`, released 2026-09-29; developers.openai.com model and pricing pages, learn.chatgpt.com, openai/codex release notes and bundled `models.json`, verified 2026-09-30): $2 in / **$0.10 cache read** / $2.50 cache write / $10 out; Batch and Flex 50%; Fast 2× price. API: 1.05M context (922K max input, 128K max output), cutoff 2026-04-30, efforts `low`…`max` (`none` dropped). Codex catalog: priority 1, default effort **`low`**, adds `ultra`, 272K/872K context, `node_repl_auto_review_required: true`, `multi_agent_version: v2` with `multi_agent_reasoning_effort: xhigh`. Credits per Mtok (input / cached / output): **50 / 2.5 / 250**; Plus local messages per 5h estimate 15–160. Rollout: Plus, Pro, Business, Enterprise/Edu (admin-enabled) in the CLI and desktop app; Codex cloud availability and the cloud default model are undocumented. No GPT-6.1 Astra or Luna (TechCrunch, citing the WSJ, 2026-09-29: 6.1 Astra cancelled; no OpenAI statement). Independent: Vals.ai Terminal-Bench 4.0 55.05% ± 1.82 (rank 5/31); system card addendum (deploymentsafety.openai.com/gpt-6-1-sol) ExploitBench 99.7% vs sol-6 81.7% and astra 100%. Vendor claim (launch post 403 to every fetcher; unverified): DeepSWE v1.1 matches astra at one-fifth the cost.

**GPT-6 Luna** (`gpt-6-luna`, released 2026-09-22 with the now off-ladder `gpt-6-sol`; verified 2026-09-22): $0.10 in / $0.01 cache read / $0.125 cache write / $0.50 out (sol-6 $2 / $0.20 / $2.50 / $10). 1.05M context (the Codex catalog exposes 272K, max 872K), cutoff 2026-05-18. Credits per Mtok: luna-6 2.5 / 0.25 / 12.5 (sol-6 50 / 5 / 250). Plus local messages per 5h (estimate): luna-6 350–3,000. Efforts stop at `max` (no `ultra`); not in Codex cloud.

**GPT-6 Astra** (`gpt-6-astra`, released 2026-09-03; verified 2026-09-04, no change 2026-09-09): $10 in / $1 cache read / $12.50 cache write / $50 out; Batch and Flex 50%; Fast 2× price. 1.05M context (the CLI exposes 272K, max 872K), cutoff 2026-04-30, API efforts `low`…`max`. Not in Codex cloud. ChatGPT quota per 5h: 5–45 messages on Plus and Standard Business, 25–225 Pro 5×, 100–900 Pro 20× (Plus: 6.1-sol 15–160, luna-6 350–3,000) — the number that governs a subscription-pool fleet. Vendor system card: astra followed 0% of injected message-board instructions, and OpenAI states its evals do not cover agents of the same user talking to each other inside one Codex harness, which it observed internally: keep worker workspaces isolated.

**All three:** above 272K input the *whole request* bills 2× input and cache, 1.5× output.

**Subscription metering** (learn.chatgpt.com/docs/pricing, verified 2026-09-10, rates re-checked 2026-09-30): Codex usage is per-token credits, one credit = $0.04, at rates equal to API list price (credit figures above); reasoning tokens bill as output; no flat per-message charge, so an API price change passes straight through to quota. The Plus "messages per 5h" figures are estimates derived from those rates. Cloud chats draw more allowance than local messages; `codex exec` is a local message on the same pool. Weekly limits exist but are unpublished. The Codex config reference lists `model_reasoning_effort` only up to `xhigh`; `max` works on the CLI — trust the CLI.

**Claude anchors and parity** (Anthropic pricing pages, verified 2026-09-22; Sonnet 5.5 2026-09-30): Opus 5.5 $4 / $20, cache read $0.20, cache write $5, fast mode $8 / $40; Sonnet 5.5 $2 / $10, cache read $0.20; Fable 5.1 $10 / $50, cache read $0.25. Opus 5.5 is below Fable 5.1 on every line and above it on Terminal-Bench 4.0, CursorBench 4.0 and the AA index (evidence below), so it is the price basis for lead comparisons; the orchestrator itself is whichever model runs the session, never a pinned model (user, 2026-09-30). Astra costs 2.5× Opus 5.5 per token and 5× on cache reads. 6.1-sol matches Sonnet 5.5's list price with half its cache-read price; luna-6 owns the cheap context-free tier. A self-`fork` from an Opus 5.5 session rereads the prefix at $0.20/Mtok (2× cold luna-6 input) and bills output at $20, the same per output token as an opus implementer.

## Fast mode

Fast mode needs **both** `-c service_tier=fast` **and** `--enable fast_mode`, is ChatGPT-auth only, and burns 2.5× included usage / 2× purchased credits (docs 2026-09-30). No catalog entry sets a default service tier (server catalog checked 2026-09-30), so an exec dispatch without `-c service_tier` bills Standard. Irrelevant for background workers, whose latency the orchestrator absorbs.

## Profiles vs pinned flags

The dispatch template pins flags explicitly so the skill is self-contained regardless of `~/.codex/config.toml`. Profiles — `-p <name>` layering `~/.codex/<name>.config.toml` — can replace the pins, but codex hard-errors if legacy `[profiles.*]` tables remain in `config.toml`; explicit flags are more portable.

## Reaching GPT models from inside Workflow scripts

Workflow scripts' `model:`/`agentType:` params only take Claude values. Reach a GPT model by wrapping: spawn a cheap Claude agent (`model: 'sonnet'`, `effort: 'low'`) instructed to compose the self-contained spec, run `codex exec` per `SKILL.md`, verify, and return the last-message file's content verbatim. A Workflow resume whose run journal is missing fails with a clear error; in auto mode, `agent()` calls with large output schemas go through the classifier.

## codex mcp-server (deprecated 2026-08-24)

Deprecated per the Codex changelog: use the Codex app server, or `codex-plugin-cc` from inside Claude Code. Build nothing on it; background `codex exec` keeps the kill/steer control this skill relies on.

## Native Codex multi-agent

Codex can spawn its own sub-agent threads, configured under `[agents]` in config.toml (`enabled` default true, `max_threads`, `default_subagent_model` / `default_subagent_reasoning_effort`, per-role `[agents.<role>]` tables). This skill doesn't orchestrate through it: V2 subagents live behind parent-owned mailboxes and the app-server *rejects* external input to a spawned child (openai/codex#27173), so an outside orchestrator cannot steer inside a worker's fan-out. A worker fanning out internally is fine; you verify the final diff. Delegation policy is `none` / `explicitRequestOnly` (new-thread default) / `proactive`, with `ultra` as the documented proactive trigger: a lane-lead brief must request the fan-out in words; never use `ultra` to get `proactive`, and expect no steering inside the lane. `spawn_agents_on_csv` was removed in 0.145.0 (#34413) though the docs still describe it. The 0.159.2 catalog gives gpt-6.1-sol `multi_agent_reasoning_effort: xhigh`, so a 6.1-sol lane lead's subagents run at `xhigh` whatever the parent's effort — the cost to model in the lane-lead A/B. Per-subagent model assignment ("leaf model", #36892) would not lift the steering objection.

## Standing roles (portability bootstrap)

SKILL.md routes to standing roles in `~/.claude/agents/`. The role files ship in this skill's `agents/` folder — install with `cp agents/*.md ~/.claude/agents/`, then dispatch **next turn** (a new or edited role file registers only at the turn boundary). On an update, compare shipped and installed copies, preserve unrelated local changes, and sync only the changed roles; editing `agents/` alone does not update the installed copies. A running session may retain previously loaded instructions, so do not assume an edit was applied to work already in flight. Roles exist because effort is frontmatter-only. (Project roles live in that project's `.claude/agents/` and are not shipped here.)

Shipped roles: `scout-high` (sonnet/high, read-only tools plus an exact-name allowlist of Linear, Google Drive, and Claude Docs read tools; server-level `mcp__<server>` patterns would also grant their write tools); `implementer-opus-med` / `-opus-xhigh` (one body; `effort` and the tier words in `description` differ); `pr-reviewer-med` / `-xhigh` / `-max` (one body; `effort` and the routing clause in `description` differ, `-max` carries the user-gated clause); `researcher-opus-med` / `-opus-high` (one body; read-only, no Write tool, reports via Bash to the brief-named path, preload frontier-search); `docs-sync-sonnet-high` (sonnet/high, all tools except `Agent` and `NotebookEdit`, edits only brief-named doc paths). Retired — delete any installed copy: `scout-low`, `implementer-sonnet-high`, `implementer-opus-low`, `implementer-opus-high`, `pr-reviewer-high`. Frontmatter surface used: `name`, `description`, `model`, `effort`, `tools`, `disallowedTools`, `skills`, `hooks`.

Role bodies separate **fixed rules**, which a brief can't relax, from **defaults**, which the brief overrides: scope, method, source window, return shape, report path. Every body says CLAUDE.md's approval, planning, and PR-landing rules belong to the lead. The read-only roles (scout, researcher, reviewer) run `~/.claude/hooks/role-guard.py` as a frontmatter `PreToolUse(Bash)` hook that denies git and GitHub mutations, including through wrappers, `sh -c`, `eval`, scripts, aliases, and curl/wget/HTTPie writes to the GitHub API. It allows `--help`, supported `--dry-run` forms, a detached worktree under a temp folder (how a reviewer runs code at the reviewed commit), and writes inside a throwaway repo whose git dir is under a temp folder; a `cd` counts only when it certainly ran, so join `cd` to git with `&&`. Each deny message names the read-only alternative before the `ESCALATE` instruction. Tests: `test_role_guard.py`; `replay_role_guard.py` replays past read-only subagent Bash calls from `~/.claude/projects`. Neither hook ships with this skill, and the command ends in `|| true`, so on a machine without them the roles run on their text rules alone. The hook is what enforces the floor: in a live probe (2026-09-24) a scout asked by a brief to commit attempted the commit, and the hook blocked it. Claude Code also injects a subagent note: "Do NOT Write report/summary/findings/analysis .md files … the parent agent reads your text output". Every role that writes a report says this note doesn't cover its report, because the lead reads that file.

## Cross-session messaging fine print

Loops self-terminate (rate-limit, dedupe, 50/100 caps). The hold-then-drop path: an unset-`crossSessionInbound` bypass receiver *holds* messages from non-bypass senders, then drops them after `dialogExpiry` (default 5 min); start messageable workers with `crossSessionInbound: "accept"` in `--settings`. Interactive sessions set accept/hold/refuse and expiry via `/config`. A `refuse` receiver and rate-limit/full-inbox drops report back to the sender — hold-then-expire is the only silent failure. `SendMessage` delivers to a bare name matching one live session (`name-word-word` variants on collision); oversized and rapid-burst messages are refused up front.

Same-machine delivery rides a per-session unix socket (`/status` → `Peer address`); each session exports `CLAUDE_CODE_MESSAGING_SOCKET`/`_TOKEN` to hooks and Bash, so a script can post into its own session — a push upgrade over polling progress files (first auth line: `{"type":"auth","token":...}`). Cross-machine and cloud routes go through Anthropic servers via Remote Control; containers can't reach host sessions. `dialogExpiry: "never"` keeps default-held messages until session end. Agent-team teammates are a separate roster, never listed by `ListAgents`; structured team protocol messages stay within the team.

## Agent teams mechanics

(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`, enabled in user settings): peer Claude sessions with a shared dependency-tracked task list, inter-agent messaging, plan-approval gates, and quality hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted` — exit 2 sends feedback and keeps the teammate working). Every session is one implicit team: spawn teammates via the Agent tool's `name` param and message them by name (`TeamCreate`/`TeamDelete` are gone — guides describing them are stale). Subagent definitions double as teammate roles (`tools`/`model` honored; `skills`/`mcpServers` ignored); teammates inherit the lead's model and effort unless the spawn names one or `CLAUDE_CODE_SUBAGENT_MODEL` is set. **Naming trap:** any named Agent spawn launches as a teammate, even during ordinary delegation. Its final answer rides in the idle notification, but it gets no auto worktree and carries team-lifecycle cost; set the env var to `0` (hot-applied) to get named subagents back. Split panes need tmux or iTerm2+`it2`. Cost: official estimate ~7× a standard session with plan-mode teammates (3–5 Sonnet teammates, ~5–6 tasks each, shut down when done). Limits: no `/resume`/`/rewind` of in-process teammates, no nested teams, no background subagents from an in-process teammate, task status can lag, one team per session, no worktree isolation — partition by file ownership (task-claim locks don't guard file edits). On disk: mailboxes `~/.claude/teams/{team}/inboxes/{agent}.json`, roster `~/.claude/teams/{team}/config.json` (brief teammates to read it to find peers), tasks `~/.claude/tasks/{team}/` (the task list survives resume; in-process teammates don't). Team and cross-session messaging share one `SendMessage` tool (cross-session is plain text only). Managed settings that deny `SendMessage`/`ListAgents` also remove subagent and teammate messaging, silently disarming SendMessage-resume.

## Review and repair evidence (added 2026-09-09)

Why send-backs carry a diagnosed defect, why reviewers get artifacts rather than transcripts, and why the repair count follows the task:

- **Repair or Resample? (arXiv:2608.25920, 2026-08-26):** 536 annotated multi-agent failure trajectories; unguided reruns reproduced 67.97% of failures and repaired 6.90%, symptom-driven intervention repaired 20.15%. A re-dispatch without a diagnosed defect is a resample, not a repair — the directing table's send-back row and the per-task repair count rest on this.
- **The Interaction Tax (ICML 2026, arXiv:2608.23541, 2026-08-24):** when agents read each other's complete outputs, proposals converge within one round; "multi-agent performance depends less on the number of agents than on the information they exchange." Reviewers get the diff and the author's report as leads, never the author's verdict or transcript; scouts feed implementers by artifact path.
- **Adversarial Review (arXiv:2608.18167, 2026-08-16):** a reviewer plus a critic that audits the review beat a five-agent baseline on LiveCodeBench with three agents; the naive protocol hit a false-consensus mode on SWE-PRBench until the prompt demanded explicit, evidence-grounded disagreement. Evidence for "findings are claims, not verdicts" and CONFIRMED/PLAUSIBLE labelling — not, on its own, grounds for a standing critic role.
- **Anthropic, Patterns and problems in multiagent systems (2026-08-13):** 18 of 30 agents chose the identical branch name; a job-queue fleet polling at 30 Hz issued 2.4M requests and accepted 117 jobs. The lead assigns branch and worktree names; workers never poll.
- **Codex-session exercise (2026-09-09):** a successor worker silently adopted a checkpoint's task id that did not match its brief; a status-file write was refused under model-reviewed auto-approval and a read-only CHECKPOINT turn was the working fallback. Source of the identity-mismatch rule, the repair-count column, and the `--approve-for-me` progress-file caveat.
- **Send-back cap (2026-09-10, local overnight Codex usage report):** a terra `max` implementer was auto-resumed through eight turns and four rejected review checkpoints overnight — 1,399 responses and 801k output tokens, 30% of all local Codex output that night — and the orchestrator never surfaced the repeated rejections. Hence the default directing-table checkpoint at a second rejected review. An explicit applicable user/project operating agreement can supersede that default; record the source and resolved policy as described in [briefs and repairs](references/briefs-and-repairs.md#task-record-and-resume-check).

## Context fuse evidence (added 2026-08-25)

Why the fuse is semantic-trigger + orchestrator-choice, not a token cap:

- **Anthropic, effective context engineering (2025):** three long-horizon tools — compaction (preserve decisions/unresolved bugs, drop stale tool output), structured note-taking (artifact survives context resets), sub-agents (explore on tens of thousands of tokens, return 1–2k distilled). Choose by task shape. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **Anthropic, long-running harnesses (Nov 2025 + Mar 2026 follow-up, via cross-model sweep):** compaction alone insufficient; structured handoff + fresh session beat continued compaction on Sonnet 4.5 ("context anxiety"), while Opus 4.5 ran fine on continuous compaction — reset policy is model/workload-dependent: an orchestrator judgment, not architecture. https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Handoff Debt (arXiv:2606.02875):** 181 takeover tasks — context-bearing handoffs cut successor agent events 20–59% and prompt tokens 42–63% vs cold takeover; structured/summary notes beat raw traces. Respawn-from-artifact is cheap when the artifact is good.
- **Governance decay (arXiv:2606.22528):** 1,323 episodes, 7 model families — 0% policy violations with constraints in context, ~30% avg (up to 59%) after compaction dropped them; constraint pinning restores 0%. This is why respawn briefs restate the standing clauses and why worker auto-compaction is never trusted to preserve them.
- **Engram (arXiv:2603.21321):** fresh successors with empty context + persistent digest/archive outperform both raw-history transfer and no-handoff; the distilled digest matters more than the raw archive.
- **Cognition, multi-agents that work (Apr 2026):** clean-context reviewers beat context-sharing ones ("context rot"; avg 2 bugs/PR caught); single-writer + intelligence-contributing helpers. https://cognition.com/blog/multi-agents-working
- **Convergent synthesis (both research tracks):** compact within a coherent phase; respawn at phase boundaries, on drift, or for independent review; summaries are navigation aids while artifacts/files stay the authority (Manus: drop content only with a restorable handle). Trigger-policy confidence is moderate — model- and workload-dependent; the architecture (external state + structured handoff + semantic triggers) is the high-confidence part.

## Claude harness fine print

Version-specific and rarely needed Claude-side mechanics; the hot-path rules stay in `SKILL.md` (Claude worker mechanics).

- **Resume and cache:** a per-invocation `model` sticks across `SendMessage` resume. Resume is cache-stable from 2.1.265 (2.1.267 for appended-system-prompt roles and forked background workers). Subagent transcripts: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`.
- **Cross-session messaging** is on by default: `SendMessage`/`ListAgents` reach independent sessions (background, `claude -p`, other terminals, cloud); plain text only. `notify_when_idle` hears a peer finish without polling. Delivery fine print: the Cross-session messaging section above.
- **Effort and roles:** `effort: low`→`max` in frontmatter overrides session effort on every model; capped by any `maxEffortLevel` setting. `--append-subagent-system-prompt-file` extends every role's prompt at launch. `experimental.cacheTtl: "1h"` in a role file keeps a long-lived role's prefix warm (session-wide: `subagentPromptCacheTtl`). `claude --agents '<json>'` at launch is session-scoped, immediate, and accepts `effort`. Headless `claude -p --agent <role>` ignores the role file's `effort:` (the Agent tool honors it); pass `--effort`.
- **Model resolution:** per-invocation `model` > frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` (a default, not an override) > inherit; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` makes the env var win. A *restricted* requested model warns and runs the parent model. `model: fable` roles honour a `[1m]` tag on `ANTHROPIC_DEFAULT_FABLE_MODEL`.
- **Output handling:** `taskOutputMaxChars` (≤128K) sets how much task output arrives inline before spilling to a file (disk copy capped at 1 GB) — raise it for large-diff legs. A mid-stream cut auto-continues; a subagent that `SendMessage`-resumed another agent is woken by its completion; subagent-started background commands have no one-hour cap. `subagent_tokens` lands only at completion (a worker cannot count its own tokens — hence the semantic context fuse).
- **Worktrees:** `worktree.baseRef` accepts `"head"` only, not branch names — provision manually for a branch base. Commands that resolve to the main checkout fail inside a worktree.
- **Fan-out env:** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20; resumes take a slot); no lifetime cap. `--max-budget-usd` halts background subagents too. Background runs keep Read/Grep/Glob/Bash/Edit/Write/WebFetch/WebSearch/Skill/ToolSearch/SendMessage + MCP. MCP calls over 2 minutes auto-background. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces every subagent foreground. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` hot-disables the teammate naming trap.
- **Headless and forks:** `subagent_type: "fork"` inherits your full conversation and prompt cache, always runs on your model, and is exempt from the depth cap. `claude -p --bare` is the headless worker for scripts/CI only (a `cd` persists across stream-json turns). An exact-id `-p --resume` failed once, unexplained, on 2.1.266 after the headless run had exited 0 — seed a fresh `-p` from the artifact rather than debug it. `-p`/SDK forking needs `CLAUDE_CODE_FORK_SUBAGENT=1`. `/fork` spawns an independent background session (keeps the parent cache; managed by `claude attach/logs/stop/respawn`); `/subtask` is the in-session variant. A `/fork`/`claude agents` session that changed code commits and pushes before finishing.

## Codex flag fine print

Since 0.154.0 `exec` has `--worktree` (see watch items), `--ignore-rules`, `--thread-source` and `--dangerously-bypass-hook-trust`; the helper uses none of them. The `exec` flag surface is byte-identical from 0.155.1 to 0.159.2 (`codex-rs/exec/src/cli.rs`): `-p <name>` layers `$CODEX_HOME/<name>.config.toml`, and `--enable/--disable <feature>` equals `-c features.<name>`. Since 0.156.0 `exec --json` keeps `web_search` actions and results (expect that item kind in events files); 0.159.0 protects `.aws` directories under writable roots and keeps explicit filesystem denials on approved commands.

Standard starts/resumes/forks use [the dispatch helper and run record](references/runtime.md#dispatch-from-one-record). It pins model/effort/cwd and separates artifacts; it does not select a tier or widen the chosen permissions. A 2026-09-11 session audit found two omitted-flag resumes despite the written rule, so these settings are required input rather than inherited intent. Actual runtime settings still require observed evidence.

- `--strict-config` errors on unrecognized keys — pair it with the pins. `codex doctor --json` reports the resolved `model` and version at zero tokens (batch preflight). The planning tool is off by default (`tools.update_plan.enabled = true` restores), so JSONL carries no plan items.
- `--ephemeral` skips session files (forfeits resume — fails loudly); `--add-dir <dir>` grants extra writable roots beyond `--cd`; `-i <file>` attaches images on dispatch and resume.
- `resume --last` is cwd-filtered (`--all` lifts it); exec-spawned threads only have UUIDs; "restore working directory" is TUI-only; resume emits a warning error item when the model resets to the config default, and only the *permission profile* is restored.
- `review --title` needs `--commit` only when used alone.
- Manual `exec resume` / `exec fork` (outside the helper) runs in the invoking cwd and rejects `--cd`/`-C` and `-s`; pin sandbox through config and keep every other helper flag. No `exec --full-auto`; use `-s workspace-write`. `--search` is TUI-only; exec web search is `-c web_search="live"`.
- JSONL `item.*` events carry `command_execution` (command, exit code, output), `file_change`, `web_search`, `agent_message`, `reasoning`; a run ends `turn.completed` or `turn.failed`.
- Effort scale: `minimal` is pre-5.6 legacy; `ultra` is ChatGPT-auth only (the API rejects it); `persistent` is a binary enum outside the catalog. Catalog defaults drift without a CLI update (watch items) — the reason `-m` and `-c model_reasoning_effort` are always passed.
- Dispatch chains: join with `;` not `&&` after `git commit` — a no-op commit exits non-zero and kills the chain.
- `browser_use` / `computer_use` / `image_generation` feature flags are stable and enabled; verify on first headless use.
