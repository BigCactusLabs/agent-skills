## OpenAI pricing detail (GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna)

**GPT-6.1 Sol** (`gpt-6.1-sol`, released 2026-09-29; developers.openai.com model and pricing pages, learn.chatgpt.com, openai/codex release notes and bundled `models.json`, verified 2026-09-30): $2 in / **$0.10 cache read** / $2.50 cache write / $10 out; Batch and Flex 50%; Fast 2× price. API: 1.05M context (922K max input, 128K max output), cutoff 2026-04-30, efforts `low`…`max` (`none` dropped). Codex catalog: priority 1, default effort **`low`**, adds `ultra`, **500K**/872K context (raised from 272K on 2026-10-11 for Codex and Work, with no long-context fee on subscription usage: [Tibo](https://x.com/thsottiaux/status/2109430343346581527), [fee post](https://x.com/thsottiaux/status/2109430894604026039); the live `models_cache.json` shows 500000 on 0.164.0, the bundled `models.json` still 272K, and the API still reprices above 272K). Credits per Mtok (input / cached / output): **50 / 2.5 / 250**; Plus local messages per 5h estimate 15–160. Codex cloud availability and the cloud default model are undocumented. Independent: Vals.ai Terminal-Bench 4.0 55.05% ± 1.82 (rank 5/31).

**GPT-6 Luna** (`gpt-6-luna`, released 2026-09-22; verified 2026-09-22): $0.10 in / $0.01 cache read / $0.125 cache write / $0.50 out. 1.05M context (the Codex catalog exposes 272K, max 872K), cutoff 2026-05-18. Credits per Mtok: 2.5 / 0.25 / 12.5. Plus local messages per 5h (estimate): 350–3,000. Efforts stop at `max` (no `ultra`); not in Codex cloud.

**GPT-6 Astra** (`gpt-6-astra`, released 2026-09-03; verified 2026-09-04, no change 2026-09-09): $10 in / $1 cache read / $12.50 cache write / $50 out; Batch and Flex 50%; Fast 2× price. 1.05M context (the CLI exposes 272K, max 872K), cutoff 2026-04-30, API efforts `low`…`max`. Not in Codex cloud. ChatGPT quota per 5h: 5–45 messages on Plus and Standard Business, 25–225 Pro 5×, 100–900 Pro 20× — the number that governs a subscription-pool fleet. OpenAI's system card says its evals do not cover agents of one user talking to each other inside one Codex harness, which it observed internally: keep worker workspaces isolated.

**Long context:** on the API, above 272K input the *whole request* bills 2× input and cache, 1.5× output, on all three. In Codex on the subscription, 6.1-sol runs a 500K default window with no long-context fee; what usage above 500K costs is unannounced. Astra and luna keep the 272K Codex window.

**Subscription metering** (learn.chatgpt.com/docs/pricing, verified 2026-09-10, rates re-checked 2026-09-30): Codex usage is per-token credits, one credit = $0.04, at rates equal to API list price (credit figures above); reasoning tokens bill as output; no flat per-message charge, so an API price change passes straight through to quota. The Plus "messages per 5h" figures are estimates derived from those rates. Cloud chats draw more allowance than local messages; `codex exec` is a local message on the same pool. Weekly limits exist but are unpublished. The Codex config reference lists `model_reasoning_effort` only up to `xhigh`; `max` works on the CLI — trust the CLI. From the Codex lead's posts (no docs page yet): auto-review, the model reviewer that answers approval prompts, has been free for ChatGPT-signed-in users since 2026-10-06 and draws no plan usage ([Day 2.1](https://x.com/thsottiaux/status/2107368734981517634)). Since about 2026-10-20 the API offers 12-hour prompt caching, and for signed-in Codex and Work users "we keep cache forever", so resuming an old thread is "guaranteed to hit the cache" ([Day 16](https://x.com/thsottiaux/status/2112712984644784534); limits unstated, and practitioners are measuring it). A reported Day 19 fix (2026-10-24) stops a mid-conversation reasoning-effort change from invalidating the cache ([summary](https://x.com/AGTPinsights/status/2113841575080182156), not Tibo's post). Together these make an `exec resume`, including a same-thread effort step after a depth failure, cache-warm on the subscription pool however long the lead waited; unmeasured locally.

**Claude anchors and parity** (Anthropic pricing pages, verified 2026-09-22; Sonnet 5.5 2026-09-30): Opus 5.5 $4 / $20, cache read $0.20, cache write $5, fast mode $8 / $40; Sonnet 5.5 $2 / $10, cache read $0.10 (halved 2026-10-07, was $0.20); Fable 5.2 (`claude-fable-5-2`, released 2026-11-09, the `fable` alias since 2.1.321) $8 / $40, cache read $0.20; Fable 5.1 (legacy) $10 / $50, cache read $0.25. Haiku 5.5 (released 2026-10-07; pricing page verified 2026-10-11) $0.10 / $0.50, cache read $0.01, 1h cache write $0.20 for prompts up to 100K tokens, and $0.50 / $2.50, cache read $0.05, 1h write $1 above it; the threshold counts cache reads and writes, so a headless `claude -p` in this environment (~125K-token prefix per turn, measured 2026-10-11) always bills the upper tier, while an in-session subagent starts at 12–32K and crosses it only on long legs. Opus 5.5 is below Fable 5.2 on input and output and equal on cache reads, and above Fable 5.1 on Terminal-Bench 4.0, CursorBench 4.0 and the AA index (evidence below; Fable 5.2's figures are unread, a watch item), so it is the price basis for lead comparisons; the orchestrator itself is whichever model runs the session, never a pinned model (user, 2026-09-30). Astra costs 2.5× Opus 5.5 per token and 5× on cache reads. 6.1-sol matches Sonnet 5.5's list and cache-read prices; luna-6 owns the cheap context-free tier. A self-`fork` from an Opus 5.5 session rereads the prefix at $0.20/Mtok (2× cold luna-6 input) and bills output at $20, the same per output token as an opus implementer.

## Fast mode

Needs **both** `-c service_tier=fast` **and** `--enable fast_mode`, ChatGPT auth only, at 2.5× included usage / 2× purchased credits (docs 2026-09-30); no catalog entry defaults to it, so an exec dispatch bills Standard. Not used for background workers, whose latency the orchestrator absorbs. The same holds for Ultrafast (`service_tier: "ultrafast"`: API astra 2026-09-29, 6.1-sol 2026-10-08; Codex feature `ultrafast_mode` stable since 0.162.0 and enforced separately from Fast).

## Reaching GPT models from inside Workflow scripts

Workflow scripts' `model:`/`agentType:` params only take Claude values. Reach a GPT model by wrapping: spawn a cheap Claude agent (`model: 'sonnet'`, `effort: 'low'`) instructed to compose the self-contained spec, run `codex exec` per `references/runtime.md`, verify, and return the last-message file's content verbatim. A Workflow resume whose run journal is missing fails with a clear error; since 2.1.305 a resume serves completed `pipeline()` and `parallel()` agents from the journal instead of re-running them, though a failed agent still re-runs every agent started after it. A run does not continue on its own after the session is backgrounded; Claude must relaunch it. Limits: 16 concurrent agents by default (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`, 1–256), 4,096 items per `parallel()`/`pipeline()`, 1,000 agents per run ([docs](https://code.claude.com/docs/en/workflows#behavior-and-limits)); in auto mode, `agent()` calls with large output schemas go through the classifier.

## Native Codex multi-agent

Codex can spawn its own sub-agent threads, configured under `[agents]` in config.toml (`enabled` default true, `max_threads`, `default_subagent_model` / `default_subagent_reasoning_effort`, per-role `[agents.<role>]` tables). This skill doesn't orchestrate through it: the app-server *rejects* external input to a spawned child (openai/codex#27173; #33885, asking to let children accept steering, is open), so an outside orchestrator cannot steer inside a worker's fan-out. A worker fanning out internally is fine; you verify the final diff. Delegation policy is `none` / `explicitRequestOnly` (new-thread default) / `proactive`, with `ultra` as the documented proactive trigger: a lane-lead brief must request the fan-out in words, and `ultra` is never the way to get `proactive`. The catalog gives gpt-6.1-sol `multi_agent_reasoning_effort: xhigh`, so a 6.1-sol parent's subagents run at `xhigh` whatever its own effort. Checked on 0.164.0 and not adoptable for cross-agent messaging: agent message boards (configured only by an embedding host through the Rust API), the inter-agent lifecycle hooks (#55657, an internal extension API), and `preModelRequest`/`postModelRequest` hooks (observation-only, never control flow). `wake_on_agent_messages` (off by default) starts a new root turn when a child's message arrives after the parent finished; `exec` workers don't need it because the skill reads the run's final diff.

## Subagent role frontmatter (`.claude/agents/*.md`)

Beyond `tools`/`model`/`effort`: `disallowedTools` (denylist, applied before `tools`; both accept `mcp__<server>` patterns), `permissionMode` (**not used, because it's ignored here**: since 2.1.267 a subagent runs in the parent's mode when the parent is in `bypassPermissions`, `acceptEdits`, or auto, and one that declares `bypassPermissions` keeps the parent's mode otherwise. With `defaultMode: bypassPermissions` in user settings, workers run bypass; write safety comes from `tools`/`disallowedTools` and the read-only roles' guard hook), `omitClaudeMd` (2.1.271; not used, because workers need CLAUDE.md's style, user-agent, and sourcing rules; each role body instead assigns its approval and PR rules to the lead), `maxTurns`, `skills` (preload full skill content at startup, no `Skill` tool needed; the researchers preload frontier-search), `mcpServers` (scope an MCP server to the worker so its tool schemas never touch main context — inline defs connect only for the worker's lifetime), `memory: user|project|local` (persistent cross-session agent memory; **not used**: it force-enables Read, Write, and Edit, which would unlock the read-only roles, and it adds an unreviewed input the brief does not control), `color` (set per role since 2026-11-01 so the task list tells them apart), `hooks` (e.g. a `PreToolUse` validator as a hard constraint where prose briefs are soft), `background`, `isolation: worktree`, `experimental.cacheTtl: "5m"|"1h"` (per-agent prompt-cache TTL, used when no `subagentPromptCacheTtl` setting is configured), `autoCompactWindow` (2.1.296; not used: it can only compact *earlier* than the main window, and compaction drops standing constraints, which is why the context fuse is a semantic checkpoint). `skills` preloads at most 32 (2.1.295). `claude --debug` names unrecognized frontmatter fields with a typo hint (2.1.296): run it once after a role edit. A `maxEffortLevel` setting (top-level or per model under `modelSettings`) caps frontmatter effort; whether it also caps the Agent call's `effort` is undocumented, and none is set here.

## Standing roles (portability bootstrap)

SKILL.md routes to standing roles in `~/.claude/agents/`. The role files ship in this skill's `agents/` folder — install with `cp agents/*.md ~/.claude/agents/`, then dispatch on the **next user turn** (a new or edited role file registers only at a user turn boundary; on 2.1.289 a turn started by a background-task notification still ran the old definition). On an update, compare shipped and installed copies, preserve unrelated local changes, and sync only the changed roles; editing `agents/` alone does not update the installed copies. A running session may retain previously loaded instructions, so do not assume an edit was applied to work already in flight. One role per job: a role's frontmatter `effort` is its default rung, and the Agent call's `effort` (2.1.292) selects any other. Precedence: `CLAUDE_CODE_EFFORT_LEVEL` > call `effort` > frontmatter > session, where the last step holds only on the session's model: since 2.1.317 a subagent or teammate on another model with no effort of its own uses that model's saved effort or its default (every shipped role sets its own, so routed dispatches are unaffected); forks ignore the call parameter; `CLAUDE_CODE_SUBAGENT_EFFORT` (2.1.316) sets the rung when nothing else names one, and whether it outranks frontmatter is unprobed. Live check (2026-10-13): `scout-sonnet`'s predecessor (frontmatter `high`) spawned with `effort: "medium"` logged `"effort":"medium"` on every turn of its transcript. Headless `claude -p --agent` and `claude --bg --agent` take `--effort` instead. (Project roles live in that project's `.claude/agents/` and are not shipped here.)

Shipped roles: `scout-sonnet` (sonnet/high, read-only tools plus an exact-name allowlist of Linear, Google Drive, and Claude Docs read tools; server-level `mcp__<server>` patterns would also grant their write tools); `implementer-opus` (opus, default `medium`; `xhigh` by call; `disallowedTools: Agent`, since a subagent can otherwise spawn subagents down to the depth cap and the brief already says "Do not spawn agents"); `pr-reviewer-opus` (opus, default `medium`; `xhigh` by call, `max` by call with the user's permission, which its `description` states); `researcher-opus` (opus, default `medium`; `high` by call; read-only, no Write tool, reports via Bash to the brief-named path, preloads frontier-search); `docs-sync-sonnet` (sonnet/high, all tools except `Agent` and `NotebookEdit`, edits only brief-named doc paths). Retired — delete any installed copy: `scout-low`, `implementer-sonnet-high`, `implementer-opus-low`, `implementer-opus-high`, `pr-reviewer-high`, and, merged into the roles above on 2026-10-13, `implementer-opus-med`, `implementer-opus-xhigh`, `pr-reviewer-med`, `pr-reviewer-xhigh`, `pr-reviewer-max`, `researcher-opus-med`, `researcher-opus-high`, `scout-high`, `docs-sync-sonnet-high`. The read-only roles (scout, reviewer, researcher) list `SendMessage` so they can reach the lead mid-run. The Write tool refuses report files from a subagent ("Subagents should return findings as text, not write report files", seen from 2.1.273 on), so every role writes a brief-named report path with Bash. Frontmatter surface used: `name`, `description`, `model`, `effort`, `tools`, `disallowedTools`, `skills`, `hooks` (`PreToolUse`, and `Stop`, which runs as `SubagentStop` when the role is spawned as a subagent).

Role bodies separate **fixed rules**, which a brief can't relax, from **defaults**, which the brief overrides: scope, method, source window, return shape, report path. Every body says CLAUDE.md's approval, planning, and PR-landing rules belong to the lead. The read-only roles (scout, researcher, reviewer) run `~/.claude/hooks/role-guard.py` as a frontmatter `PreToolUse(Bash)` hook that denies git and GitHub mutations, including through wrappers, `sh -c`, `eval`, scripts, aliases, and curl/wget/HTTPie writes to the GitHub API. It allows `--help`, supported `--dry-run` forms, a detached worktree under a temp folder (how a reviewer runs code at the reviewed commit), and writes inside a throwaway repo whose git dir is under a temp folder; a `cd` counts only when it certainly ran, so join `cd` to git with `&&`. Each deny message names the read-only alternative before the `ESCALATE` instruction. Tests: `test_role_guard.py`; `replay_role_guard.py` replays past read-only subagent Bash calls from `~/.claude/projects`. Neither ships with this skill, and the command ends in `|| true`, so on a machine without them the roles run on their text rules alone. The hook is what enforces the floor: in a live probe (2026-09-24) a scout asked by a brief to commit attempted the commit, and the hook blocked it. Claude Code also injects a subagent note: "Do NOT Write report/summary/findings/analysis .md files … the parent agent reads your text output". Every role that writes a report says this note doesn't cover its report, because the lead reads that file.

Two hooks do ship with the skill, in `scripts/` (tests: `test_hooks.py`):

- `message_guard.py`, a `PreToolUse(SendMessage)` hook on the read-only roles, allows only `to: "main"` (plus a team `shutdown_response`) and denies `notify_when_idle`. Without it, a read-only subagent could resume a completed write-capable sibling under its own direction (a resumed agent reports to whoever resumed it) or message another local session; the roster of named agents is in its startup context. It is wired without `|| true` and with `onFailure: block` (2.1.295), so a missing, crashing, or timed-out guard blocks the send instead of allowing it; before 2.1.295 only a missing script blocked, through Python's exit code 2, and a crash (exit 1) or timeout let the send through. The `onFailure` key in role frontmatter is docs-verified (hooks reference), not yet live-probed.
- `status_contract.py`, a `Stop` hook on every shipped role, blocks a stop once when the final message's last line is not `DONE`, `BLOCKED: …`, `ESCALATE: …`, or `CHECKPOINT: …` (an optional `Status:` label is accepted), and tells the worker to continue if its own command or unblocked work is still pending, else to resend its complete final message with the line. A worker that ends its turn while its own background command runs is woken by that command's completion and sends a second report; in transcripts from 2026-10-03 to 10-13, 17 of 20 such self-wakes followed an early "checkpoint, not done" report to the lead, so the implementer and reviewer roles wait for their checks in the foreground. Since 2.1.299 the lead's background-agent notification says when an agent is only waiting on its own background work; treat that report as interim, not as a `CHECKPOINT` to resume. It reads `last_assistant_message`, allows the stop when `stop_hook_active` is set, and fails open (`|| true`). Before 2.1.311, `SubagentStop` hooks ran about twice a minute for each running subagent instead of once at its finish, so a hook-fire count from transcripts before that version may include runs while the worker was still working; re-measure before rebuilding a rule on such a count. It sits in role frontmatter rather than settings because a settings-level `SubagentStop` hook without an agent-type matcher also fires for Claude Code's internal agents, whose `agent_type` is empty. In auto mode a worker that reports through `SubagentHandback` puts its report in that tool's input, not in `last_assistant_message`; this hook does not cover that case. A role launched as a session (`claude --bg --agent`) runs the same hook as a plain `Stop` at each turn end.

## Cross-session messaging fine print

Loops self-terminate (rate-limit, dedupe, 50/100 caps). The hold-then-drop path: an unset-`crossSessionInbound` bypass receiver *holds* messages from non-bypass senders, then drops them after `dialogExpiry` (default 5 min); start messageable workers with `crossSessionInbound: "accept"` in `--settings`. Interactive sessions set accept/hold/refuse and expiry via `/config`. A `refuse` receiver, rate-limit and full-inbox drops, and a held message all report back to the sender as not delivered, naming the session (held messages: 2.1.271 for headless senders, 2.1.288 for all; at most 100 are held). Remote Control, cloud, and Desktop receivers report nothing back. `SendMessage` delivers to a bare name matching one live session (`name-word-word` variants on collision); oversized and rapid-burst messages are refused up front.

Same-machine delivery rides a per-session unix socket (`/status` → `Peer address`); each session exports `CLAUDE_CODE_MESSAGING_SOCKET`/`_TOKEN` to hooks and Bash, so a script can post into its own session — a push upgrade over polling. Wire format: an optional `{"type":"auth","token":"<CLAUDE_CODE_MESSAGING_TOKEN>"}` line, then `{"type":"user","message":{"role":"user","content":"<text>"}}`, one JSON object per line, sent within 30 s of connecting (the message line is from 2.1.311's `--debug` log template, not the docs; [docs](https://code.claude.com/docs/en/cross-session-messaging#the-sessions-inbox-socket)). When no `crossSessionInbound` value applies, a message from the session's own child process is delivered even to a bypass session; on macOS a child that has exited is verified only by the token, so send it. It arrives as a peer message, between tool calls or as a new turn when idle (probed 2026-10-26: a token-bearing post from Bash and from the Codex ask relay both arrived mid-turn here; a tokenless post from a bypass Codex worker's shell did not arrive). The Codex ask relay rides this (`references/runtime.md`, asks). Cross-machine and cloud routes go through Anthropic servers via Remote Control; containers can't reach host sessions. `dialogExpiry: "never"` keeps default-held messages until session end. Agent-team teammates are a separate roster, never listed by `ListAgents`; structured team protocol messages stay within the team.

## Agent teams mechanics

(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`, enabled in user settings): peer Claude sessions with inter-agent messaging, a shared dependency-tracked task list (off on Opus 5.x unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`), plan-approval gates, and quality hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted`; exit 2 sends feedback and keeps the teammate working). Every session is one implicit team: spawn teammates via the Agent tool's `name` param and message them by name. Since 2.1.290 an in-process teammate's `agent_id` is its agent ID and the `name@team` address is `teammate_id`. Subagent definitions double as teammate roles (`tools`, `model`, `disallowedTools`, `effort`, and the body apply; `skills`/`mcpServers` are ignored); without one, teammates inherit the lead's model and effort (on another model, that model's saved or default effort, 2.1.317; anthropics/claude-code#80569, open, reports frontmatter `effort` ignored on teammates, which the docs contradict, unprobed here). A teammate spawned by the naming trap (`references/claude-workers.md`) returns its answer in the idle notification but gets no auto worktree and carries team-lifecycle cost; `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` (hot-applied) gives named subagents back. Cost: official estimate ~7× a standard session. Limits: no `/resume`/`/rewind` of in-process teammates, no nested teams, no background subagents from an in-process teammate, one team per session, no worktree isolation — partition by file ownership, since task-claim locks don't guard file edits. On disk: roster `~/.claude/teams/{team}/config.json` (brief teammates to read it to find peers), mailboxes under `inboxes/`, tasks `~/.claude/tasks/{team}/` (the task list survives resume; in-process teammates don't). Team and cross-session messaging share one `SendMessage` tool; managed settings that deny `SendMessage`/`ListAgents` also remove subagent and teammate messaging.

## Background sessions (agent view)

Research preview (docs: code.claude.com/docs/en/agent-view). `claude --bg [--agent <role>] [--name <n>] [--model <id>] "<prompt>"` starts a supervisor-hosted session that survives the lead's exit, keeps the full toolset, and moves into its own worktree under `.claude/worktrees/` before editing. Each session draws on the subscription like an interactive one. Sessions are local and stop if the machine shuts down.

- **State:** `claude agents --json --all` is the supported interface (the files under `~/.claude/jobs/<id>/` are not stable). Per background entry: `id` (short ID), `sessionId` (full UUID, for `claude --resume`), `name`, `state` (`working`, `blocked`, `done`, `failed`, `stopped`), and while the process lives `pid` and `status` (`busy`, `waiting`, `idle`), plus `waitingFor` when waiting. `done` means the last turn finished and the session awaits a prompt; `blocked` always needs you. Verified working on 2.1.289.
- **Control:** `claude logs|attach|stop|respawn|rm <id>`. `respawn` resumes the saved conversation, or starts an empty one when none is on disk (2.1.290). `attach` and `logs` accept part of a session name since 2.1.290, but `attach` finds a name only while the process runs, so record and use the ID. `/model`, `/effort` and `/rename` sent from `claude agents` to a busy session apply mid-turn (2.1.290): the one way to retune a running background worker without stopping it.
- **Service lifetime (macOS):** since 2.1.295, stopping `claude agents` while its background service is not running stops every running session about a minute later unless `claude agents` runs again. Whether a `claude --bg` worker launched from a plain shell, with agent view never opened, is affected is unverified; check `claude agents --json --all` after closing agent view on a long run.
- **Completion:** `SendMessage` with `notify_when_idle: true` (no message needed) gets one idle notice. It works from the main conversation only, for sessions on this machine, and expires after 12 hours; a subagent or teammate acting as lead is refused and polls `claude agents --json --all` instead. A `hold` setting on either side shows the notice in the transcript without delivering it to Claude, and `refuse` lets it expire unanswered, so keep the poll as the fallback.
- **Git:** a session that changed code in its own worktree commits without asking and pushes the branch when a remote exists; it never pushes `main`/`master`, force-pushes, or merges. Instructions in the task, CLAUDE.md, or memory that the user handles committing or pushing take precedence, so "the lead owns git" may also stop the commit; brief "commit on your branch; never push, merge, or open a PR" instead.
- **Deletion:** the agent-view delete removes a Claude-created worktree including uncommitted changes; `claude rm` keeps a worktree with uncommitted changes, and neither removes one with commits Claude Code cannot confirm are saved elsewhere.
- **Effort:** pass `--effort`; headless `--agent` ignores the role's `effort:`, and whether `--bg` applies it is unverified.
- **Time limits:** whether the unattended background-Bash cap (30 min / 2 h) applies inside a `--bg` session is unverified; its `/status` reads "background job · unattended".

## Watch items (open questions)

- **Astra lane lead (A/B-pending, no row):** one closed-ended multi-subsystem lane per dispatch, astra `high` under bypass with `--cd <lane-worktree>`, the brief saying in words "split this across subagents you spawn; you own integration" (otherwise astra works single-threaded; native Codex multi-agent above), correction by fresh dispatch. The first qualifying lane runs paired against 6.1-sol `xhigh` with the user's consent, defects counted by the cross-model reviewer; add the row on a win. Astra never gets peer orchestrator authority (its price as a session lead, and no cross-family control plane).
- **Rung logging:** per real leg, record the rung dispatched, first-try pass, and which rung rescued a failure. **Medium is the floor (user, 2026-11-01: "not interested in running low anywhere"):** no `low` rung on any Claude role, and no proposing or evaluating one, whatever first-try rates show.
- **Reviewer `max` basis:** Arena WebDev lists Opus 5.5 only at `max` (~1811 in a 2026-10-13 snapshot), with no `high` row, so the max-over-high basis is still Opus 5's (max ~1688 vs high ~1661, 2026-09-10); the local effort-tier eval covered repo review, not WebDev.
- **Subagent cache TTL (probed 2026-11-01, not adopted):** `subagentPromptCacheTtl: "1h"` hot-applies to the next spawn, and the 1h write is 2× base input against 1.25× for the 5m write (Opus 5.5: $8 vs $5 per Mtok, read $0.20). A rebuild after an idle gap costs about one 5m write of the context, so `1h` pays only when more than about six in ten runs idle past five minutes between API requests; in the background-subagent shape the 180 s auto-background keeps check waits under that, and the remaining case is a `BLOCKED:` worker resumed after a slow ruling. Adopt it on the implementer and reviewer (`experimental.cacheTtl`) if rung logging shows slow rulings are common; the frontmatter route itself is unprobed.

## Review and repair evidence (added 2026-09-09)

- **Repair or Resample? (arXiv:2608.25920):** unguided reruns repaired 6.90% of 536 multi-agent failures and reproduced 67.97%; symptom-driven intervention repaired 20.15%. Basis for the send-back row and the per-task repair count.
- **The Interaction Tax (ICML 2026, arXiv:2608.23541):** agents that read each other's complete outputs converge within one round. Basis for reviewers getting the diff and the author's report as leads, never the author's verdict or transcript, and for scouts feeding implementers by artifact path.
- **Adversarial Review (arXiv:2608.18167):** a reviewer plus a critic of the review beat a five-agent baseline; the naive protocol fell into false consensus until disagreement had to be explicit and evidence-grounded. Basis for "findings are claims" and CONFIRMED/PLAUSIBLE labels, not for a standing critic role.
- **Anthropic, Patterns and problems in multiagent systems (2026-08-13):** 18 of 30 agents chose the same branch name; a fleet polling at 30 Hz issued 2.4M requests for 117 jobs. The lead assigns branch and worktree names; workers never poll.
- **Codex-session exercise (2026-09-09):** a successor silently adopted a checkpoint task id that did not match its brief, and model-reviewed auto-approval refused a status-file write. Source of the identity-mismatch rule.
- **Send-back cap (2026-09-10):** a terra `max` implementer was auto-resumed through four rejected reviews overnight (801k output tokens, 30% of that night's local Codex output) without the lead surfacing it. Basis for the default checkpoint at a second rejected review, which an explicit user or project agreement can supersede ([briefs and repairs](references/briefs-and-repairs.md#task-record-and-resume-check)).

### Delegation and batching evidence (DeepSeek Harness, added 2026-11-01)

A second, independent source for the delegate-early rule and the lead's idle discipline, from a different lab than the Cognition figures. "Exploring Super-agent Design" (DeepSeek Harness team, 2026-11-01, https://x.com/DeepSeekHarness/status/2116857257245987236; prototype https://github.com/deepseek-ai/dsh-superagent-prototype). Synthetic workload: about 300 chat and CI messages per run, about 20 of them work requests, coding simulated by a tool that consumes time, five runs per design, so the figures measure scheduling, not code quality, and the authors call them indicative only.

| Design | Completion p50 / p95 (min) | Cache-read tokens per run |
|---|---|---|
| Two-level (router never executes; workers subscribe to their threads) | 12.4 / 15.7 | 23.2M |
| Two-level without pass-through (every follow-up via the router) | 12.6 / 15.5 | 31.8M |
| Single session + subagent tool, "use a subagent when appropriate" | 20.4 / 29.5 | 6.1M |
| Single session + subagent tool, delegation-first prompt | 13.8 / 29.0 | 10.8M |

- The neutral prompt delegated in 0 of 5 runs; the delegation-first prompt in 4 of 5, and the one run where the model judged the work "small" and did it inline set the p95. Prompt-level delegation is unreliable; the structural fix is a lead that does not execute. Basis for the "small enough to do myself" line in `SKILL.md`.
- Pass-through changed neither completion time nor quality, but cut router decisions about 30% and total cache-read tokens about 37%. Our analogue is already in place: implementers own and wait on their own checks, so machine results never route through the lead; review findings still do, on purpose, because they are claims the lead rules on.
- Router batching: with arrivals rising from about 1 to about 40 decisions per minute, mean batch size went 1.0 to 2.8, time per request 2.5 s to 3.9 s, amortized time per decision 6.4 s to 1.6 s. Basis for the drain-then-act rule: queued events are cheaper ruled on together than one turn each.
- Their router runs on a lighter model because it forwards the original request verbatim and makes no technical decisions (prototype `prompts/orchestrator.md`, `dispatch.md`). Our lead writes behavior tables, rules on findings, and merges, so the session-model rule stands; the two roles are not the same job.
- Prototype rules behind the ask clause and the `DONE` definition: a 100-word cap on chat-channel messages with evidence in the report, one concrete question at a time, "an opened pull request is not readiness", and a UI change without a real before screenshot not ready. Their "silently reproduce and fix" rule is the model for the one-speculative-read-only-leg allowance. The adopted and not-adopted ledger is in `AUDIT.md`.

## Skill size and compaction evidence (added 2026-11-09)

Why `SKILL.md`'s body stays under 19,500 characters (enforced by `scripts/test_skill_docs.py`) and step detail lives in `references/`.

- **The re-attach limit.** After auto-compaction Claude Code "re-attaches the most recent invocation of each skill after the summary, keeping the first 5,000 tokens of each", with 25,000 tokens shared across skills ([skills docs, content lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle)). Observed as a cut at exactly 20,000 characters ending "[... skill content truncated for compaction; use Read on the skill path if you need the full text]" ([obra/superpowers#2481](https://github.com/obra/superpowers/issues/2481), 2026-10-08). This file was 36,834 bytes on 2026-11-01, so the cut fell at line 113, inside playbook step 1: dispatch, supervision, verification, the directing table (repair cap, second-rejection checkpoint), fleet control, and worker pools were gone for the rest of a long session. Probed here on claude-code 2.1.321 (2026-11-09; `claude -p`, sonnet, a manual `/compact`, then asking what skill text was in context): the 36,834-byte version came back cut after 19,728 body characters and ending in that note, with four of its eight sections; the 19 KB version came back whole. So the count is characters, frontmatter excluded, and it includes a header carrying the skill's path (about 270 characters with a 148-character path), which leaves about 19,800 body characters at the installed path. When the limit was introduced is unverified.
- **The same fix elsewhere.** superpowers v7.0.1 (2026-10-21) moved step content to `references/` "read from disk at the step that needs it" and added a CI test that fails any `SKILL.md` at 20,000 bytes ([release](https://github.com/obra/superpowers/releases/tag/v7.0.1)). Its subagent-driven-development skill is 2,897 words after the trim; this one is about 2,900.
- **What a move costs.** Wang et al. ([arXiv 2610.04832](https://arxiv.org/abs/2610.04832)): removing a rule lowers compliance by 0.27–0.33; a rule moved to an on-demand file keeps about half its effect (51%, CI 28–75%) unless the agent is told when to read it; unrelated text of the same length has no measured effect; the gains come from rules that name a command or path. Hence the "Read at the step, every time" table with one trigger per file, and the routing short form kept in `SKILL.md`.
- **Length itself.** SkillReducer ([arXiv 2603.29919](https://arxiv.org/abs/2603.29919)): over 60% of skill body text was non-actionable in its sample, and a 39% compression raised task quality 2.8%. The Agent Skills spec recommends a body under 5,000 tokens ([specification](https://agentskills.io/specification)). A rule-count cliff by about 80 rules ([arXiv 2607.19257](https://arxiv.org/abs/2607.19257)) was not measured on Claude: a lead, not a basis.

## Context fuse evidence (added 2026-08-25)

Why the fuse is a semantic trigger plus the orchestrator's choice, not a token cap:

- **Anthropic (effective context engineering, 2025; long-running harnesses, Nov 2025 + Mar 2026):** compaction, note-taking and distilling sub-agents are the long-horizon tools; a fresh session with a structured handoff beat continued compaction on Sonnet 4.5 while Opus 4.5 ran fine on compaction, so reset policy is a judgment per model and workload. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents · https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Handoff Debt (arXiv:2606.02875) and Engram (arXiv:2603.21321):** context-bearing handoffs cut successor events 20–59% and prompt tokens 42–63% against cold takeover; a fresh successor with a distilled digest beats raw-history transfer.

- Confidence in the trigger policy is moderate; the architecture (external state, structured handoff, semantic triggers) is the high-confidence part.

## Claude harness fine print

Version-specific and rarely needed Claude-side mechanics; the rules a lead needs before its first Claude dispatch are in `references/claude-workers.md`.

- **Resume and cache:** a per-invocation `model` sticks across `SendMessage` resume. Resume and mid-run messages are cache-stable within the prompt-cache TTL (five minutes for subagents unless `subagentPromptCacheTtl` or a role's `experimental.cacheTtl` says `1h`), so a steer costs no cache rebuild; a worker idle past the TTL, such as one resumed after a slow `BLOCKED:` ruling, rewrites its whole prefix (46K tokens in the 2026-11-01 probe). Subagent transcripts: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`. An agent the user stopped (`x` in `/tasks`) refuses `SendMessage` with "agent was cancelled". Finished subagents stay listed under `/tasks` "Earlier in this session" and can be reopened and messaged after they leave the list or the session restarts (2.1.319). Since 2.1.317 a message to a running background agent moves that agent's running command to the background without stopping it, so a steer no longer waits out a long call; whether a foreground subagent behaves the same is unprobed. A send to a name a newer agent took is refused, and the error names where the name now points; retarget by agent ID.
- **Cross-session messaging** is on by default: `SendMessage`/`ListAgents` reach independent sessions (background, `claude -p`, other terminals, cloud); plain text only. `notify_when_idle` hears a peer finish without polling. Delivery fine print: the Cross-session messaging section above.
- **Effort and roles:** `effort: low`→`max` in frontmatter overrides session effort on every model, and the Agent call's `effort` (2.1.292) overrides frontmatter and persists across resume (standing roles above); frontmatter is capped by any `maxEffortLevel` setting. `/tasks` names each subagent's model and effort. `--append-subagent-system-prompt-file` extends every role's prompt at launch. `experimental.cacheTtl: "1h"` in a role file keeps a long-lived role's prefix warm (session-wide: `subagentPromptCacheTtl`). `claude --agents '<json>'` at launch is session-scoped, immediate, and accepts `effort`. Headless `claude -p --agent <role>` ignores the role file's `effort:` (the Agent tool honors it); pass `--effort`.
- **Model resolution:** per-invocation `model` > frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` (a default, not an override) > inherit; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` makes the env var win. A *restricted* requested model warns and runs the parent model. `model: fable` roles honour a `[1m]` tag on `ANTHROPIC_DEFAULT_FABLE_MODEL`.
- **Output handling:** `TaskOutput` was removed in 2.1.277 and `taskOutputMaxChars` does nothing since; read a background task's output file with `Read`. A mid-stream cut auto-continues, and a hard API-error death reports as failure with partial output (retry once the error clears, don't escalate); a subagent that `SendMessage`-resumed another agent is woken by its completion. Background Bash commands stop at 30 min by default and 2 h at most only in unattended sessions (`-p`, Agent SDK, CI, cloud; 2.1.285, scoped 2.1.288), and at 10 min by default in a `-p` run whose prompt is passed as text rather than stream-json ([docs](https://code.claude.com/docs/en/tools-reference); 2.1.321 corrected what Claude is told), which kills a Codex worker mid-run: pass an explicit timeout on the launch or raise `BASH_DEFAULT_TIMEOUT_MS` / `BASH_MAX_TIMEOUT_MS`. Interactive sessions have no cap. `subagent_tokens` lands only at completion (a worker cannot count its own tokens — hence the semantic context fuse).
- **Worktrees:** `worktree.baseRef` accepts `"fresh"` (default: the remote default branch) or `"head"` (local HEAD with unpushed commits, not uncommitted edits), never a branch name — provision manually for a branch base ([docs](https://code.claude.com/docs/en/worktrees#choose-the-base-branch)). Commands that resolve to the main checkout fail inside a worktree.
- **Fan-out env:** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20; resumes take a slot); no lifetime cap. `--max-budget-usd` halts background subagents too. Background runs keep every MCP tool and only these built-ins: Read, Grep, Glob, LSP, Bash, PowerShell, Edit, Write, NotebookEdit, WebFetch, WebSearch, TodoWrite, Skill, ToolSearch, EnterWorktree, ExitWorktree, Monitor, TaskStop, SendMessage, Artifact (Agent and ExitPlanMode follow their own rules). MCP calls over 2 minutes auto-background, and a background subagent's Bash call is moved to the background after 180 s whatever its `timeout` (probed 2026-11-01, on every provider since 2.1.318; an in-process teammate's call runs to the timeout), so a worker's gap between API requests stays under the five-minute cache TTL while it waits on a check. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces every subagent foreground. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` hot-disables the teammate naming trap. `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` (2.1.296) runs every Workflow agent on one model while other subagents keep theirs.
- **Headless and forks:** `subagent_type: "fork"` inherits your full conversation and prompt cache, always runs on your model, and is exempt from the depth cap. `claude -p --bare` is the headless worker for scripts/CI only (a `cd` persists across stream-json turns). A one-shot `claude -p` waits for its background commands and scheduled wakeups after the final result and names them on stderr; a wrapper timeout must allow for that tail. Since 2.1.302 fork subagents are on by default in `-p`, the Agent SDK, the desktop app and VS Code (`CLAUDE_CODE_FORK_SUBAGENT=0` turns them off), and there a subagent's own Agent calls run in the foreground by default; since 2.1.307 forks launched together are each told which launch is theirs, so sibling forks rarely start each other's work. `/fork` spawns an independent background session (keeps the parent cache; git behavior and control as in background sessions); `/subtask` is the in-session variant.

## Codex flag fine print

The `exec` flag surface (`codex-rs/exec/src/cli.rs`) and the JSONL event schema have been stable across the pinned versions (tag diffs in `AUDIT.md`). The helper uses none of `--worktree` (watch items), `--thread-source` or `--dangerously-bypass-hook-trust`. It passes `--ignore-rules` in both sandbox modes, because an execpolicy `allow` rule runs its command outside the sandbox ([runtime.md](references/runtime.md#what-the-sandbox-does-not-stop)). `--enable/--disable <feature>` equals `-c features.<name>`. `-p <name>` layers `$CODEX_HOME/<name>.config.toml`; a profile could replace the pins, but codex hard-errors while legacy `[profiles.*]` tables remain in `config.toml`, so the helper pins flags and ignores the user's config. Events files carry `web_search` items; `.aws` directories under writable roots stay protected, and explicit filesystem denials hold on approved commands.

Standard starts/resumes/forks use [the dispatch helper and run record](references/runtime.md#dispatch-from-one-record). It pins model/effort/cwd and separates artifacts; it does not select a tier or widen the chosen permissions. A 2026-09-11 session audit found two omitted-flag resumes despite the written rule, so these settings are required input rather than inherited intent. Actual runtime settings still require observed evidence.

- `--strict-config` errors on unrecognized keys — pair it with the pins. `codex doctor --json` reports the resolved `model` and version at zero tokens (batch preflight). The planning tool is off by default (`tools.update_plan.enabled = true` restores), so JSONL carries no plan items.
- `--ephemeral` skips session files (forfeits resume — fails loudly); `--add-dir <dir>` grants extra writable roots beyond `--cd` on `exec` only: `exec resume` and `exec fork` reject it (0.167.0), so the helper sets `sandbox_workspace_write.writable_roots` with `-c`, which all three accept (live resume, 2026-11-10). Never add the repository's `.git` as a root: it does not let a linked worktree commit (`index.lock` in the worktree's gitdir is still denied), and it makes the repository's `config` and `hooks/` writable (`codex sandbox` with `sandbox_workspace_write.writable_roots`, run from the linked worktree, 0.166.0 and 0.167.0, 2026-11-09). The 11-06 note read the failed commit as the whole root staying unwritable, which was wrong; its matching claim for a permission-profile write rule has not been re-probed. Practitioner fixes that add the git common dir ([sequant#1076](https://github.com/sequant-io/sequant/issues/1076), [bernstein#5375](https://github.com/sipyourdrink-ltd/bernstein/pull/5375), both on older CLIs) fail on these versions, so the helper adds the worktree's gitdir and the shared `objects`, `refs`, and `logs` instead, which leaves `config` and `hooks/` read-only. Permission profiles (`default_permissions`, `[permissions.*]`) are ignored whenever `sandbox_mode` is set in any loaded config file or with `--sandbox` ([docs](https://developers.openai.com/codex/permissions)), which the user's `config.toml` and the helper both do; `-i <file>` attaches images on dispatch and resume.
- `--output-schema <file>` holds only on tool-light turns (openai/codex#19816): a tool-heavy job that must return a schema runs two-phase, a work turn and then a schema-only resume turn, validated locally.
- `resume --last` is cwd-filtered (`--all` lifts it); exec-spawned threads only have UUIDs; "restore working directory" is TUI-only; resume emits a warning error item when the model resets to the config default. Resume restores the saved permissions and network approvals (0.163.0, #53150) and the saved service tier, reasoning summary and personality (0.164.0, #55923), unless the caller overrides them. Whether an unpinned exec resume now keeps the thread's model is unprobed; the helper passes model and effort on every resume anyway.
- `review --title` needs `--commit` only when used alone. Top-level `codex review` lacks `-m` and `--json`: pin the model with `-c model="..."`, or use `codex exec review`.
- Manual `exec resume` / `exec fork` (outside the helper) runs in the invoking cwd and rejects `--cd`/`-C` and `-s`; pin sandbox through config and keep every other helper flag. No `exec --full-auto`; use `-s workspace-write`. `--search` is TUI-only; exec web search is `-c web_search="live"`.
- JSONL `item.*` events carry `command_execution` (`command`, `exit_code`, `aggregated_output`, `status` `completed`/`failed`), `file_change` (`changes[]` of absolute `path` and `kind`), `web_search`, `agent_message`, `reasoning`; a run ends `turn.completed` or `turn.failed`. A turn interrupted by SIGINT makes `exec` exit 1 within about two seconds and writes no closing event and no `--output-last-message` file; the rollout records `turn_aborted` (reason `interrupted`), the running command dies with the process, and `exec resume` on the thread works, with the model told the turn was interrupted (live, 0.160.0, `AUDIT.md` 2026-10-03). The handler is registered only after the session is configured (`exec/src/lib.rs`).
- Effort scale: `minimal` is pre-5.6 legacy; `ultra` is ChatGPT-auth only (the API rejects it); `persistent` is a binary enum outside the catalog. Catalog defaults drift without a CLI update: `~/.codex/models_cache.json` is etag-refreshed from the server and sets the bare default (gpt-6.1-sol at `low` since 0.159.1; `codex doctor --json` shows it), which is why `-m` and `-c model_reasoning_effort` are always passed.
- Dispatch chains: join with `;` not `&&` after `git commit` — a no-op commit exits non-zero and kills the chain.
- `browser_use` / `computer_use` / `image_generation` feature flags are stable and enabled; verify on first headless use.

## Codex hooks fine print

`scripts/codex_steer.py` depends on these (docs at [learn.chatgpt.com/docs/hooks](https://learn.chatgpt.com/docs/hooks); source read at tags `rust-v0.163.0` and `rust-v0.164.0`; live probes per CLI version in `AUDIT.md`, latest codex-cli 0.167.0 on 2026-11-09: seven runs, the six hook-side checks passing in all seven, the `PreToolUse` hold included, and two runs each failing a worker-compliance check). The trust hash of user hooks is the declaration hash; plugin hooks also hash the plugin's contents (#54619). Hook `additionalContext` and `Stop` continuation text carry `harness` provenance metadata through prompt assembly (#53831). Since 0.166.0 `PreToolUse`, `PermissionRequest`, and `PostToolUse` hooks receive the command's resolved workdir as `cwd` (#57198, #57203), unused by the steer hook. Codex has twelve hook events: `SessionStart`, `SessionEnd`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `Interrupt`.

- **Trust.** Hooks load from `$CODEX_HOME/hooks.json`, `config.toml` `[hooks]`, a trusted project's `.codex/`, plugins, and `-c hooks.*`. `codex exec` skips an untrusted hook silently, with no warning ([openai/codex#46210](https://github.com/openai/codex/issues/46210), open; [#48715](https://github.com/openai/codex/issues/48715) closed as its duplicate). Trust is recorded only through `/hooks` in the interactive CLI, as `hooks.state."<source>:<event>:<group>:<handler>".trusted_hash`. The hash covers the definition (event, matcher, command, timeout), not the script it runs, and the key includes the hook's position, so moving or editing the entry needs trust again. `--dangerously-bypass-hook-trust` waives trust for every user, project, session-flag, and plugin hook in that invocation ([manaflow-ai/cmux#8136](https://github.com/manaflow-ai/cmux/issues/8136); `hooks/src/engine/discovery.rs`). Practitioners pass it with inline `-c hooks.*` ([csmoot99/Mafioso#4](https://github.com/csmoot99/Mafioso/pull/4)) or only inside a sealed container with plugins off ([rjwalters/loom#10109](https://github.com/rjwalters/loom/pull/10109)); the skill uses neither.
- **PostToolUse.** `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"..."}}` becomes a developer message before the next model request. Shell (`exec_command`), `apply_patch`, MCP tools, and code-mode nested calls fire it; hosted web search does not. A long command's PostToolUse can arrive on a later `write_stdin` poll, when the command finishes. Output over about 2,500 tokens per hook message spills to a file and the model sees a preview (`hooks/src/output_spill.rs`; `additionalContextLimit` per handler; flopwire [`hook-caps-2026-10-03.md`](https://github.com/flopwire/flopwire/blob/main/notes/log/hook-caps-2026-10-03.md)). `codex_steer.py` caps a steer at 8,000 bytes to stay under it.
- **PreToolUse.** Fires before shell (`exec_command`), `apply_patch`, MCP, and other local tool calls; hosted web search does not fire it, and a `write_stdin` poll does not re-run it. `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}` blocks the call and hands the reason to the model; the output also accepts `additionalContext`, and `permissionDecision: "allow"` with `updatedInput`. With several hooks, the first block reason in configured order wins, so a hook at a lower index decides first. Input carries `tool_name`, `tool_input`, `tool_use_id`, `turn_id`, `session_id`, and `agent_id`. The default timeout is 600 s; `install` sets 5. `codex_steer.py` denies only to deliver an urgent steer, and relays every ask here, so a waiting ask reaches the lead before `wait` starts polling. Since 0.167.0 `PreToolUse` hooks also run before the `--approve-for-me` reviewer's policy checks (#58368; unprobed here, the pin is 0.166.0). If another `PreToolUse` hook blocks the same call first, its reason wins and the steer's is lost though the receipt says delivered; on this machine the steer hook is the only `PreToolUse` entry in `~/.codex/hooks.json`.
- **Stop.** `{"decision":"block","reason":"..."}` (or exit 2) continues the same turn with the reason as the next prompt. Codex has no loop cap; the input carries `stop_hook_active` and `last_assistant_message`, and the output has no `additionalContext`. A hook that crashes must exit 1 (reported, non-blocking), never 2.
- **Subagents.** Hooks fire inside Codex subagent threads with the root's `session_id`; a child sets `agent_id`, and its `transcript_path` rollout UUID differs from `session_id` (flopwire [`hook_subagent.go`](https://github.com/flopwire/flopwire/blob/main/cmd/flopwire/hook_subagent.go)). The steer hook acts only on the root thread.
- **Compliance.** Models treat an unannounced hook message as possible injection and may refuse it; a standing instruction in the brief naming the channel fixes that ([flopwire probes](https://github.com/flopwire/flopwire/blob/main/notes/log/probes-2026-10-01.md); [Delgado, 2026-05](https://cdelgado70.github.io/2026/05/09/hooks-and-the-wrapper-authority-problem.html)). A steer that contradicts the brief reads as injection too, which is why goal reversals go in a resume brief.
- **Limits.** Hooks never wake an idle session and never preempt a response in flight; delivery waits for the next tool call (its start, for an urgent steer) or the stop. `SessionStart` `additionalContext` was reported rejected ([#45999](https://github.com/openai/codex/issues/45999), closed as not planned 2026-09-17), so nothing re-injects after compaction. Other designs: [pirate/codex-structured-steering](https://github.com/pirate/codex-structured-steering) injects a `<steering_surface>` block as hook `additionalContext`; [c2c](https://c2c.im/client-delivery/) drains an inbox through hooks and uses app-server `thread/inject_items` in managed mode; flopwire ([plan](https://github.com/flopwire/flopwire/blob/main/notes/message-bus/plan.md)) adds leases and redelivery the skill does not need for one lead.
