## OpenAI pricing detail (GPT-6 Astra + GPT-5.6)

**GPT-6 Astra** (`gpt-6-astra`, released 2026-09-03; official model + pricing pages verified 2026-09-04, API changelog re-checked 2026-09-09 — no price change): $10 in / $1 cache read / $12.50 cache write / $50 out per Mtok; above 272K input the *whole request* bills 2× input and cache, 1.5× output ($20 / $75); Batch and Flex 50%; Fast 2× price ("2× speed, increased usage"). 1.05M context (922K max input, 128K max output; the CLI exposes 272K, max 872K), cutoff 2026-04-30, API efforts `low`…`max` only. Single variant — no mini/nano/pro, and no GPT-6 cheap tier, so luna stays the floor. Not offered in Codex cloud (sol is). ChatGPT quota per 5h window: astra 5–45 messages on Plus and Standard Business, 25–225 Pro 5×, 100–900 Pro 20× — vs sol 10–100, terra 25–200, luna 250–2,000 on Plus: roughly ½ sol and 1/50 luna per message, which is the number that governs a subscription-pool fleet. Capability: Anthropic's 2026-09-01 table has Fable 5.1 at 55.8% Terminal-Bench 4.0 vs sol 37.3%; the only astra number (57.9%, secondhand from press) is unverified — pair astra with Fable 5.1 on price, not benchmark. Independent: ARC-AGI-3 99.9% at `high` (arcprize.org, 2026-09-03), Artificial Analysis index 61 (#8 of 201). Vendor system card: astra followed 0% of injected message-board instructions vs sol 52% — and OpenAI states its evals do not cover agents of the same user talking to each other inside one Codex harness, which it observed internally: keep worker workspaces isolated.

**GPT-5.6.** Since the 2026-07-30 cuts: luna −80% to $0.20/$1.20 per Mtok, terra −20% to $2/$12. **Subscription metering (learn.chatgpt.com/docs/pricing, verified 2026-09-10):** Codex usage is per-token credits, one credit = $0.04, rates equal API list price exactly — astra 250 / 25 / 1,250, sol 100 / 10 / 500, terra 50 / 5 / 300, luna 5 / 0.5 / 30 credits per Mtok (input / cached / output); reasoning tokens bill as output; no flat per-message charge, so any API price change passes straight through to quota. ## Fast mode

Fast mode needs **both** `-c service_tier=fast` **and** `--enable fast_mode`, is ChatGPT-auth only, and burns credits at 2.5× (measured on the prior generation). API side: Fast mode replaced Priority Processing 2026-07-30 — sol only, 2× price for up to 2.5× speed — irrelevant for background workers, whose latency the orchestrator absorbs.

## Profiles vs pinned flags

The dispatch template pins flags explicitly so the skill is self-contained regardless of `~/.codex/config.toml`. Profiles — `-p <name>` layering `~/.codex/<name>.config.toml` — can replace the pins, but codex hard-errors if legacy `[profiles.*]` tables remain in `config.toml`; explicit flags are more portable.

## Reaching GPT models from inside Workflow scripts

Workflow scripts' `model:`/`agentType:` params only take Claude values. Reach astra or gpt-5.6 by wrapping: spawn a cheap Claude agent (`model: 'sonnet'`, `effort: 'low'`) instructed to compose the self-contained spec, run `codex exec` per `SKILL.md`, verify, and return the last-message file's content verbatim. Harness drift: a Workflow resume whose run journal is missing now fails with a clear error instead of rerunning every agent (2.1.265); `agent()` calls with large output schemas are checked by the classifier rather than refused in auto mode (2.1.267).

## Native Codex multi-agent (v2 stable as of 0.145.0)

Codex can spawn its own sub-agent threads; settings unified under `[agents]` in config.toml (verified against 0.145.0 source: `enabled` default true, an enabled `features.multi_agent_v2` takes precedence; `max_concurrent_threads_per_session` alias `max_threads`; `default_subagent_model` / `default_subagent_reasoning_effort`; per-role `[agents.<role>]` tables; `max_depth` is V1-only). ## Subagent role frontmatter (`.claude/agents/*.md`)

Beyond `tools`/`model`/`effort`: `disallowedTools` (denylist, applied before `tools`; both accept `mcp__<server>` patterns), `permissionMode` (**every role file carries `permissionMode: bypassPermissions`, read-only roles included** — write safety comes from `tools`/`disallowedTools`; without it a background worker's sandbox escapes (scratchpad writes, vitest temp dirs, network) surface as permission prompts in the main session, measured 2026-09-01), `maxTurns`, `skills` (preload full skill content at startup), `mcpServers` (scope an MCP server to the worker so its tool schemas never touch main context — inline defs connect only for the worker's lifetime), `memory: user|project|local` (persistent cross-session agent memory), `hooks` (e.g. a `PreToolUse` validator as a hard constraint where prose briefs are soft), `background`, `isolation: worktree`, `experimental.cacheTtl: "5m"|"1h"` (2.1.248 — per-agent prompt-cache TTL, used when no `subagentPromptCacheTtl` setting is configured). **`effort:` was silently ignored on models whose default effort is pinned (Fable 5, Opus 4.7/4.8) before 2.1.267**; a `maxEffortLevel` setting (top-level or per model under `modelSettings`, 2.1.267) caps what any role can request.

## Cross-session messaging fine print

Windows support landed 2.1.241. Loops self-terminate (rate-limit, dedupe, 50/100 caps). The hold-then-drop path: an unset-`crossSessionInbound` bypass receiver *holds* messages from non-bypass senders, then drops after `dialogExpiry` (default 5 min); interactive sessions set accept/hold/refuse and expiry via `/config`. Since 2.1.238 a `refuse` receiver and rate-limit/full-inbox drops report back to the sender — hold-then-expire is the only path still failing silently. `SendMessage` delivers to a bare name matching one live session (`name-word-word` variants on collision); oversized and rapid-burst messages are refused up front.

Same-machine delivery rides a per-session unix socket (`/status` → `Peer address`); each session exports `CLAUDE_CODE_MESSAGING_SOCKET`/`_TOKEN` to hooks and Bash, so a script can post into its own session — a push upgrade over polling progress files (first auth line: `{"type":"auth","token":...}`). Cross-machine and cloud routes go through Anthropic servers via Remote Control; containers can't reach host sessions. `dialogExpiry: "never"` keeps default-held messages until session end. Agent-team teammates are a separate roster, never listed by `ListAgents`; structured team protocol messages stay within the team.

## Agent teams mechanics

(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`): peer Claude sessions with a shared dependency-tracked task list, inter-agent messaging, plan-approval gates, and quality hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted` — exit 2 sends feedback and keeps the teammate working). Enabled in user settings 2026-08-02. Verified against docs/changelog: since v2.1.178 every session is one implicit team — spawn teammates via the Agent tool's `name` param, message by name (`team_name` ignored; `TeamCreate`/`TeamDelete` removed — guides describing them are stale). Subagent definitions double as teammate roles (`tools`/`model` honored; `skills`/`mcpServers` ignored). Since v2.1.234 teammates inherit the lead's model and effort unless the spawn names one or `CLAUDE_CODE_SUBAGENT_MODEL` is set. Since 2.1.265 teammates and resumed subagents keep SubagentStart hook context and preloaded skills inside the cached prefix on later turns (a cache-miss class before). **Naming trap:** any named Agent spawn launches as a teammate — even self-named during ordinary delegation. Its final answer rides in the idle notification, but it is still a teammate (no auto worktree, team-lifecycle semantics, top cost surface); set the env var to `0` (hot-applied) to get named subagents back. Display default is `in-process` since v2.1.179; split panes need tmux or iTerm2+`it2` (not VS Code terminal/Windows Terminal/Ghostty). Cost: official estimate ~7× a standard session with plan-mode teammates — Sonnet teammates, 3-5 of them, ~5-6 tasks each, shut down when done. Limits: no `/resume`/`/rewind` of in-process teammates (lead may message dead teammates after resume), no nested teams, no background subagents from an in-process teammate, task-status can lag, one lead/team per session, no automatic worktree isolation — partition by file ownership; task-claim locks don't guard file edits. On disk (docs 2026-08-13): mailboxes `~/.claude/teams/{team}/inboxes/{agent}.json`, roster `~/.claude/teams/{team}/config.json` (teammates can read it to discover peers — brief them to), tasks `~/.claude/tasks/{team}/` — the task list survives resume; in-process teammates don't. Teammates never appear in `ListAgents`: team roster and cross-session messaging are separate namespaces sharing one `SendMessage` tool (cross-session is plain text only). Org kill switch: managed settings denying `SendMessage`/`ListAgents` also remove subagent and teammate messaging — SendMessage-resume can be silently disarmed in a managed org.

## Review and repair evidence (added 2026-09-09)

Why send-backs carry a diagnosed defect, why reviewers get artifacts rather than transcripts, and why the repair count follows the task:

- **Repair or Resample? (arXiv:2608.25920, 2026-08-26):** 536 annotated multi-agent failure trajectories; unguided reruns reproduced 67.97% of failures and repaired 6.90%, symptom-driven intervention repaired 20.15%. A re-dispatch without a diagnosed defect is a resample, not a repair — the directing table's send-back row and the per-task repair count rest on this.
- **The Interaction Tax (ICML 2026, arXiv:2608.23541, 2026-08-24):** when agents read each other's complete outputs, proposals converge within one round; "multi-agent performance depends less on the number of agents than on the information they exchange." Reviewers get the diff and the author's report as leads, never the author's verdict or transcript; scouts feed implementers by artifact path.
- **Adversarial Review (arXiv:2608.18167, 2026-08-16):** a reviewer plus a critic that audits the review beat a five-agent baseline on LiveCodeBench with three agents; the naive protocol hit a false-consensus mode on SWE-PRBench until the prompt demanded explicit, evidence-grounded disagreement. Evidence for "findings are claims, not verdicts" and CONFIRMED/PLAUSIBLE labelling — not, on its own, grounds for a standing critic role.
- **Anthropic, Patterns and problems in multiagent systems (2026-08-13):** 18 of 30 agents chose the identical branch name; a job-queue fleet polling at 30 Hz issued 2.4M requests and accepted 117 jobs. The lead assigns branch and worktree names; workers never poll.
- **Codex-session exercise (2026-09-09, validation report kept locally):** a successor worker silently adopted a checkpoint's task id that did not match its brief; a status-file write was refused under model-reviewed auto-approval and a read-only CHECKPOINT turn was the working fallback. Source of the identity-mismatch rule, the repair-count column, and the `--approve-for-me` progress-file caveat. Unverified lead from the same pass: a Feb 2026 paper on consensus-over-expertise losses (up to 37.6%) surfaced only in a search snippet.

- **Send-back cap (2026-09-10, local overnight Codex usage report):** a terra `max` implementer on proofset task 22 was auto-resumed through eight turns and four rejected review checkpoints, 10:44 p.m. to 7:01 a.m., 1,399 responses and 801k output tokens (30% of all local Codex output that night). In its solo window, 12:49 to 5:49 a.m., the weekly meter moved three points on ~520k output tokens, so the whole session cost roughly 4–5 of the 21 points lost overnight; the rest was evening concurrency across five projects. The orchestrator never surfaced the repeated rejections. Hence the directing-table row: second rejected review on a task stops for a user ruling instead of a third auto-resume.

## Context fuse evidence (added 2026-08-25)

Why the fuse is semantic-trigger + orchestrator-choice, not a token cap:

- **Anthropic, effective context engineering (2025):** three long-horizon tools — compaction (preserve decisions/unresolved bugs, drop stale tool output), structured note-taking (artifact survives context resets), sub-agents (explore on tens of thousands of tokens, return 1–2k distilled). Choose by task shape. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **Anthropic, long-running harnesses (Nov 2025 + Mar 2026 follow-up, via cross-model sweep):** compaction alone insufficient; structured handoff + fresh session beat continued compaction on Sonnet 4.5 ("context anxiety"), while Opus 4.5 ran fine on continuous compaction — reset policy is model/workload-dependent: an orchestrator judgment, not architecture. https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Handoff Debt (arXiv:2606.02875):** 181 takeover tasks — context-bearing handoffs cut successor agent events 20–59% and prompt tokens 42–63% vs cold takeover; structured/summary notes beat raw traces. Respawn-from-artifact is cheap when the artifact is good.
- **Governance decay (arXiv:2606.22528):** 1,323 episodes, 7 model families — 0% policy violations with constraints in context, ~30% avg (up to 59%) after compaction dropped them; constraint pinning restores 0%. This is why respawn briefs restate the standing clauses and why worker auto-compaction is never trusted to preserve them.
- **Engram (arXiv:2603.21321):** fresh successors with empty context + persistent digest/archive outperform both raw-history transfer and no-handoff; the distilled digest matters more than the raw archive.
- **Cognition, multi-agents that work (Apr 2026):** clean-context reviewers beat context-sharing ones ("context rot"; avg 2 bugs/PR caught); single-writer + intelligence-contributing helpers. https://cognition.com/blog/multi-agents-working
- **Convergent synthesis (both research tracks):** compact within a coherent phase; respawn at phase boundaries, on drift, or for independent review; summaries are navigation aids while artifacts/files stay the authority (Manus: drop content only with a restorable handle). Trigger-policy confidence is moderate — model- and workload-dependent; the architecture (external state + structured handoff + semantic triggers) is the high-confidence part.
