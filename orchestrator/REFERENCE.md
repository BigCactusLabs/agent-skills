# Orchestrator — cold-path reference

Material consulted rarely: read the section you need, not the file. Hot-path mechanics (dispatch, supervise, resume, pools) live in `SKILL.md`. Verification history: `AUDIT.md`.

## OpenAI pricing detail (GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna)

**GPT-6.1 Sol** (`gpt-6.1-sol`, released 2026-09-29; developers.openai.com model and pricing pages, learn.chatgpt.com, openai/codex release notes and bundled `models.json`, verified 2026-09-30): $2 in / **$0.10 cache read** / $2.50 cache write / $10 out; Batch and Flex 50%; Fast 2× price. API: 1.05M context (922K max input, 128K max output), cutoff 2026-04-30, efforts `low`…`max` (`none` dropped). Codex catalog: priority 1, default effort **`low`**, adds `ultra`, 272K/872K context, `node_repl_auto_review_required: true`, `multi_agent_version: v2` with `multi_agent_reasoning_effort: xhigh`. Credits per Mtok (input / cached / output): **50 / 2.5 / 250**; Plus local messages per 5h estimate 15–160. Codex cloud availability and the cloud default model are undocumented. Independent: Vals.ai Terminal-Bench 4.0 55.05% ± 1.82 (rank 5/31); system card addendum (deploymentsafety.openai.com/gpt-6-1-sol) ExploitBench 99.7% (astra 100%).

**GPT-6 Luna** (`gpt-6-luna`, released 2026-09-22; verified 2026-09-22): $0.10 in / $0.01 cache read / $0.125 cache write / $0.50 out. 1.05M context (the Codex catalog exposes 272K, max 872K), cutoff 2026-05-18. Credits per Mtok: 2.5 / 0.25 / 12.5. Plus local messages per 5h (estimate): 350–3,000. Efforts stop at `max` (no `ultra`); not in Codex cloud.

**GPT-6 Astra** (`gpt-6-astra`, released 2026-09-03; verified 2026-09-04, no change 2026-09-09): $10 in / $1 cache read / $12.50 cache write / $50 out; Batch and Flex 50%; Fast 2× price. 1.05M context (the CLI exposes 272K, max 872K), cutoff 2026-04-30, API efforts `low`…`max`. Not in Codex cloud. ChatGPT quota per 5h: 5–45 messages on Plus and Standard Business, 25–225 Pro 5×, 100–900 Pro 20× — the number that governs a subscription-pool fleet. OpenAI's system card says its evals do not cover agents of one user talking to each other inside one Codex harness, which it observed internally: keep worker workspaces isolated.

**All three:** above 272K input the *whole request* bills 2× input and cache, 1.5× output.

**Subscription metering** (learn.chatgpt.com/docs/pricing, verified 2026-09-10, rates re-checked 2026-09-30): Codex usage is per-token credits, one credit = $0.04, at rates equal to API list price (credit figures above); reasoning tokens bill as output; no flat per-message charge, so an API price change passes straight through to quota. The Plus "messages per 5h" figures are estimates derived from those rates. Cloud chats draw more allowance than local messages; `codex exec` is a local message on the same pool. Weekly limits exist but are unpublished. The Codex config reference lists `model_reasoning_effort` only up to `xhigh`; `max` works on the CLI — trust the CLI.

**Claude anchors and parity** (Anthropic pricing pages, verified 2026-09-22; Sonnet 5.5 2026-09-30): Opus 5.5 $4 / $20, cache read $0.20, cache write $5, fast mode $8 / $40; Sonnet 5.5 $2 / $10, cache read $0.10 (halved 2026-10-07, was $0.20); Fable 5.1 $10 / $50, cache read $0.25. Haiku 5.5 (released 2026-10-07; pricing page verified 2026-10-11) $0.10 / $0.50, cache read $0.01, 1h cache write $0.20 for prompts up to 100K tokens, and $0.50 / $2.50, cache read $0.05, 1h write $1 above it; the threshold counts cache reads and writes, so a headless `claude -p` in this environment (~125K-token prefix per turn, measured 2026-10-11) always bills the upper tier, while an in-session subagent starts at 12–32K and crosses it only on long legs. Opus 5.5 is below Fable 5.1 on every line and above it on Terminal-Bench 4.0, CursorBench 4.0 and the AA index (evidence below), so it is the price basis for lead comparisons; the orchestrator itself is whichever model runs the session, never a pinned model (user, 2026-09-30). Astra costs 2.5× Opus 5.5 per token and 5× on cache reads. 6.1-sol matches Sonnet 5.5's list and cache-read prices; luna-6 owns the cheap context-free tier. A self-`fork` from an Opus 5.5 session rereads the prefix at $0.20/Mtok (2× cold luna-6 input) and bills output at $20, the same per output token as an opus implementer.

## Fast mode

Needs **both** `-c service_tier=fast` **and** `--enable fast_mode`, ChatGPT auth only, at 2.5× included usage / 2× purchased credits (docs 2026-09-30); no catalog entry defaults to it, so an exec dispatch bills Standard. Not used for background workers, whose latency the orchestrator absorbs. The same holds for Ultrafast (`service_tier: "ultrafast"`: API astra 2026-09-29, 6.1-sol 2026-10-08; Codex feature `ultrafast_mode` stable since 0.162.0 and enforced separately from Fast).

## Reaching GPT models from inside Workflow scripts

Workflow scripts' `model:`/`agentType:` params only take Claude values. Reach a GPT model by wrapping: spawn a cheap Claude agent (`model: 'sonnet'`, `effort: 'low'`) instructed to compose the self-contained spec, run `codex exec` per `SKILL.md`, verify, and return the last-message file's content verbatim. A Workflow resume whose run journal is missing fails with a clear error; in auto mode, `agent()` calls with large output schemas go through the classifier.

## Native Codex multi-agent

Codex can spawn its own sub-agent threads, configured under `[agents]` in config.toml (`enabled` default true, `max_threads`, `default_subagent_model` / `default_subagent_reasoning_effort`, per-role `[agents.<role>]` tables). This skill doesn't orchestrate through it: V2 subagents live behind parent-owned mailboxes and the app-server *rejects* external input to a spawned child (openai/codex#27173, merged 2026-06-09; #33885, asking to let children accept steering, is open), so an outside orchestrator cannot steer inside a worker's fan-out. A worker fanning out internally is fine; you verify the final diff. Delegation policy is `none` / `explicitRequestOnly` (new-thread default) / `proactive`, with `ultra` as the documented proactive trigger: a lane-lead brief must request the fan-out in words; never use `ultra` to get `proactive`, and expect no steering inside the lane. `spawn_agents_on_csv` was removed in 0.145.0 (#34413) though the docs still describe it. The 0.159.2 catalog gives gpt-6.1-sol `multi_agent_reasoning_effort: xhigh`, so a 6.1-sol lane lead's subagents run at `xhigh` whatever the parent's effort — the cost to model in the lane-lead A/B. Per-subagent model assignment ("leaf model", #36892) would not lift the steering objection.

## Subagent role frontmatter (`.claude/agents/*.md`)

Beyond `tools`/`model`/`effort`: `disallowedTools` (denylist, applied before `tools`; both accept `mcp__<server>` patterns), `permissionMode` (**not used, because it's ignored here**: since 2.1.267 a subagent runs in the parent's mode when the parent is in `bypassPermissions`, `acceptEdits`, or auto, and one that declares `bypassPermissions` keeps the parent's mode otherwise. With `defaultMode: bypassPermissions` in user settings, workers run bypass; write safety comes from `tools`/`disallowedTools` and the read-only roles' guard hook), `omitClaudeMd` (2.1.271; not used, because workers need CLAUDE.md's style, user-agent, and sourcing rules; each role body instead assigns its approval and PR rules to the lead), `maxTurns`, `skills` (preload full skill content at startup, no `Skill` tool needed; the researchers preload frontier-search), `mcpServers` (scope an MCP server to the worker so its tool schemas never touch main context — inline defs connect only for the worker's lifetime), `memory: user|project|local` (persistent cross-session agent memory), `hooks` (e.g. a `PreToolUse` validator as a hard constraint where prose briefs are soft), `background`, `isolation: worktree`, `experimental.cacheTtl: "5m"|"1h"` (per-agent prompt-cache TTL, used when no `subagentPromptCacheTtl` setting is configured), `autoCompactWindow` (2.1.296; not used: it can only compact *earlier* than the main window, and compaction drops standing constraints, which is why the context fuse is a semantic checkpoint). `skills` preloads at most 32 (2.1.295). `claude --debug` names unrecognized frontmatter fields with a typo hint (2.1.296): run it once after a role edit. A `maxEffortLevel` setting (top-level or per model under `modelSettings`) caps frontmatter effort; whether it also caps the Agent call's `effort` is undocumented, and none is set here.

## Standing roles (portability bootstrap)

SKILL.md routes to standing roles in `~/.claude/agents/`. The role files ship in this skill's `agents/` folder — install with `cp agents/*.md ~/.claude/agents/`, then dispatch on the **next user turn** (a new or edited role file registers only at a user turn boundary; on 2.1.289 a turn started by a background-task notification still ran the old definition). On an update, compare shipped and installed copies, preserve unrelated local changes, and sync only the changed roles; editing `agents/` alone does not update the installed copies. A running session may retain previously loaded instructions, so do not assume an edit was applied to work already in flight. One role per job: a role's frontmatter `effort` is its default rung, and the Agent call's `effort` (2.1.292) selects any other. Precedence: `CLAUDE_CODE_EFFORT_LEVEL` > call `effort` > frontmatter > session; forks ignore the call parameter. Live check (2026-10-13): `scout-sonnet`'s predecessor (frontmatter `high`) spawned with `effort: "medium"` logged `"effort":"medium"` on every turn of its transcript. Headless `claude -p --agent` and `claude --bg --agent` take `--effort` instead. (Project roles live in that project's `.claude/agents/` and are not shipped here.)

Shipped roles: `scout-sonnet` (sonnet/high, read-only tools plus an exact-name allowlist of Linear, Google Drive, and Claude Docs read tools; server-level `mcp__<server>` patterns would also grant their write tools); `implementer-opus` (opus, default `medium`; `xhigh` by call; `disallowedTools: Agent`, since a subagent can otherwise spawn subagents down to the depth cap and the brief already says "Do not spawn agents"); `pr-reviewer-opus` (opus, default `medium`; `xhigh` by call, `max` by call with the user's permission, which its `description` states); `researcher-opus` (opus, default `medium`; `high` by call; read-only, no Write tool, reports via Bash to the brief-named path, preloads frontier-search); `docs-sync-sonnet` (sonnet/high, all tools except `Agent` and `NotebookEdit`, edits only brief-named doc paths). Retired — delete any installed copy: `scout-low`, `implementer-sonnet-high`, `implementer-opus-low`, `implementer-opus-high`, `pr-reviewer-high`, and, merged into the roles above on 2026-10-13, `implementer-opus-med`, `implementer-opus-xhigh`, `pr-reviewer-med`, `pr-reviewer-xhigh`, `pr-reviewer-max`, `researcher-opus-med`, `researcher-opus-high`, `scout-high`, `docs-sync-sonnet-high`. The read-only roles (scout, reviewer, researcher) list `SendMessage` so they can reach the lead mid-run. The Write tool refuses report files from a subagent ("Subagents should return findings as text, not write report files", seen from 2.1.273 on), so every role writes a brief-named report path with Bash. Frontmatter surface used: `name`, `description`, `model`, `effort`, `tools`, `disallowedTools`, `skills`, `hooks` (`PreToolUse`, and `Stop`, which runs as `SubagentStop` when the role is spawned as a subagent).

Role bodies separate **fixed rules**, which a brief can't relax, from **defaults**, which the brief overrides: scope, method, source window, return shape, report path. Every body says CLAUDE.md's approval, planning, and PR-landing rules belong to the lead. The read-only roles (scout, researcher, reviewer) run `~/.claude/hooks/role-guard.py` as a frontmatter `PreToolUse(Bash)` hook that denies git and GitHub mutations, including through wrappers, `sh -c`, `eval`, scripts, aliases, and curl/wget/HTTPie writes to the GitHub API. It allows `--help`, supported `--dry-run` forms, a detached worktree under a temp folder (how a reviewer runs code at the reviewed commit), and writes inside a throwaway repo whose git dir is under a temp folder; a `cd` counts only when it certainly ran, so join `cd` to git with `&&`. Each deny message names the read-only alternative before the `ESCALATE` instruction. Tests: `test_role_guard.py`; `replay_role_guard.py` replays past read-only subagent Bash calls from `~/.claude/projects`. Neither ships with this skill, and the command ends in `|| true`, so on a machine without them the roles run on their text rules alone. The hook is what enforces the floor: in a live probe (2026-09-24) a scout asked by a brief to commit attempted the commit, and the hook blocked it. Claude Code also injects a subagent note: "Do NOT Write report/summary/findings/analysis .md files … the parent agent reads your text output". Every role that writes a report says this note doesn't cover its report, because the lead reads that file.

Two hooks do ship with the skill, in `scripts/` (tests: `test_hooks.py`):

- `message_guard.py`, a `PreToolUse(SendMessage)` hook on the read-only roles, allows only `to: "main"` (plus a team `shutdown_response`) and denies `notify_when_idle`. Without it, a read-only subagent could resume a completed write-capable sibling under its own direction (a resumed agent reports to whoever resumed it) or message another local session; the roster of named agents is in its startup context. It is wired without `|| true` and with `onFailure: block` (2.1.295), so a missing, crashing, or timed-out guard blocks the send instead of allowing it; before 2.1.295 only a missing script blocked, through Python's exit code 2, and a crash (exit 1) or timeout let the send through. The `onFailure` key in role frontmatter is docs-verified (hooks reference), not yet live-probed.
- `status_contract.py`, a `Stop` hook on every shipped role, blocks a stop once when the final message's last line is not `DONE`, `BLOCKED: …`, `ESCALATE: …`, or `CHECKPOINT: …` (an optional `Status:` label is accepted), and tells the worker to continue if its own command or unblocked work is still pending, else to resend its complete final message with the line. A worker that ends its turn while its own background command runs is woken by that command's completion and sends a second report; in transcripts from 2026-10-03 to 10-13, 17 of 20 such self-wakes followed an early "checkpoint, not done" report to the lead, so the implementer and reviewer roles wait for their checks in the foreground. Since 2.1.299 the lead's background-agent notification says when an agent is only waiting on its own background work; treat that report as interim, not as a `CHECKPOINT` to resume. It reads `last_assistant_message`, allows the stop when `stop_hook_active` is set, and fails open (`|| true`). It sits in role frontmatter rather than settings because a settings-level `SubagentStop` hook without an agent-type matcher also fires for Claude Code's internal agents, whose `agent_type` is empty. In auto mode a worker that reports through `SubagentHandback` puts its report in that tool's input, not in `last_assistant_message`; this hook does not cover that case. A role launched as a session (`claude --bg --agent`) runs the same hook as a plain `Stop` at each turn end.

## Cross-session messaging fine print

Loops self-terminate (rate-limit, dedupe, 50/100 caps). The hold-then-drop path: an unset-`crossSessionInbound` bypass receiver *holds* messages from non-bypass senders, then drops them after `dialogExpiry` (default 5 min); start messageable workers with `crossSessionInbound: "accept"` in `--settings`. Interactive sessions set accept/hold/refuse and expiry via `/config`. A `refuse` receiver, rate-limit and full-inbox drops, and a held message all report back to the sender as not delivered, naming the session (held messages: 2.1.271 for headless senders, 2.1.288 for all; at most 100 are held). Remote Control, cloud, and Desktop receivers report nothing back. `SendMessage` delivers to a bare name matching one live session (`name-word-word` variants on collision); oversized and rapid-burst messages are refused up front.

Same-machine delivery rides a per-session unix socket (`/status` → `Peer address`); each session exports `CLAUDE_CODE_MESSAGING_SOCKET`/`_TOKEN` to hooks and Bash, so a script can post into its own session — a push upgrade over polling progress files (first auth line: `{"type":"auth","token":...}`). Cross-machine and cloud routes go through Anthropic servers via Remote Control; containers can't reach host sessions. `dialogExpiry: "never"` keeps default-held messages until session end. Agent-team teammates are a separate roster, never listed by `ListAgents`; structured team protocol messages stay within the team.

## Agent teams mechanics

(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`, enabled in user settings): peer Claude sessions with a shared dependency-tracked task list (on Opus 5.x the Task tools are off, so in-process teammates coordinate by messages alone unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`), inter-agent messaging, plan-approval gates, and quality hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted` — exit 2 sends feedback and keeps the teammate working). Every session is one implicit team: spawn teammates via the Agent tool's `name` param and message them by name (`TeamCreate`/`TeamDelete` are gone). Since 2.1.290 an in-process teammate's `agent_id` (Agent results, `TaskCreated`/`TaskCompleted`/`TeammateIdle` input) is its agent ID; the `name@team` address moved to `teammate_id`, hook input's `team_name` is deprecated, and `TeammateIdle` no longer fires from a teammate's own subagents or forks. Subagent definitions double as teammate roles: `tools` and `model` apply; for an in-process teammate so do `disallowedTools`, `effort`, and the body (appended to the default prompt; a split-pane teammate uses it in place of that prompt); `skills`/`mcpServers` are ignored (`docs/agent-teams`, subagent definitions). Without a definition, teammates inherit the lead's model and effort unless the spawn names one or `CLAUDE_CODE_SUBAGENT_MODEL` is set. A teammate spawned by the naming trap (`SKILL.md`) returns its final answer in the idle notification but gets no auto worktree and carries team-lifecycle cost; setting the env var to `0` (hot-applied) gives named subagents back. Cost: official estimate ~7× a standard session with plan-mode teammates (3–5 Sonnet teammates, ~5–6 tasks each, shut down when done). Limits: no `/resume`/`/rewind` of in-process teammates, no nested teams, no background subagents from an in-process teammate, task status can lag, one team per session, no worktree isolation — partition by file ownership (task-claim locks don't guard file edits). On disk: mailboxes `~/.claude/teams/{team}/inboxes/{agent}.json`, roster `~/.claude/teams/{team}/config.json` (brief teammates to read it to find peers), tasks `~/.claude/tasks/{team}/` (the task list survives resume; in-process teammates don't). Team and cross-session messaging share one `SendMessage` tool (cross-session is plain text only). Managed settings that deny `SendMessage`/`ListAgents` also remove subagent and teammate messaging, silently disarming SendMessage-resume.

## Background sessions (agent view)

Research preview (docs: code.claude.com/docs/en/agent-view). `claude --bg [--agent <role>] [--name <n>] [--model <id>] "<prompt>"` starts a supervisor-hosted session that survives the lead's exit, keeps the full toolset, and moves into its own worktree under `.claude/worktrees/` before editing. Each session draws on the subscription like an interactive one. Sessions are local and stop if the machine shuts down.

- **State:** `claude agents --json --all` is the supported interface (the files under `~/.claude/jobs/<id>/` are not stable). Per background entry: `id` (short ID), `sessionId` (full UUID, for `claude --resume`), `name`, `state` (`working`, `blocked`, `done`, `failed`, `stopped`), and while the process lives `pid` and `status` (`busy`, `waiting`, `idle`), plus `waitingFor` when waiting. `done` means the last turn finished and the session awaits a prompt; `blocked` always needs you. Verified working on 2.1.289.
- **Control:** `claude logs|attach|stop|respawn|rm <id>`. `respawn` resumes the saved conversation, or starts an empty one when none is on disk (2.1.290). `attach` and `logs` accept part of a session name since 2.1.290, but `attach` finds a name only while the process runs, so record and use the ID. `/model`, `/effort` and `/rename` sent from `claude agents` to a busy session apply mid-turn (2.1.290): the one way to retune a running background worker without stopping it.
- **Service lifetime (macOS):** since 2.1.295, stopping `claude agents` while its background service is not running stops every running session about a minute later unless `claude agents` runs again. Whether a `claude --bg` worker launched from a plain shell, with agent view never opened, is affected is unverified; check `claude agents --json --all` after closing agent view on a long run.
- **Completion:** `SendMessage` with `notify_when_idle: true` (no message needed) gets one idle notice. It works from the main conversation only, for sessions on this machine, and expires after 12 hours; a subagent or teammate acting as lead is refused and polls `claude agents --json --all` instead. A `hold` setting on either side shows the notice in the transcript without delivering it to Claude, and `refuse` lets it expire unanswered, so keep the poll as the fallback.
- **Git:** a session that changed code in its own worktree commits without asking and pushes the branch when a remote exists; it never pushes `main`/`master`, force-pushes, or merges. Instructions in the task, CLAUDE.md, or memory that the user handles committing or pushing take precedence, so "the lead owns git" may also stop the commit; brief "commit on your branch; never push, merge, or open a PR" instead.
- **Deletion:** the agent-view delete removes a Claude-created worktree including uncommitted changes; `claude rm` keeps a worktree with uncommitted changes, and neither removes one with commits Claude Code cannot confirm are saved elsewhere.
- **Effort:** pass `--effort`; headless `--agent` ignores the role's `effort:`, and whether `--bg` applies it is unverified.
- **Time limits:** whether the unattended background-Bash cap (30 min / 2 h) applies inside a `--bg` session is unverified; its `/status` reads "background job · unattended".

## Review and repair evidence (added 2026-09-09)

- **Repair or Resample? (arXiv:2608.25920):** unguided reruns repaired 6.90% of 536 multi-agent failures and reproduced 67.97%; symptom-driven intervention repaired 20.15%. Basis for the send-back row and the per-task repair count.
- **The Interaction Tax (ICML 2026, arXiv:2608.23541):** agents that read each other's complete outputs converge within one round. Basis for reviewers getting the diff and the author's report as leads, never the author's verdict or transcript, and for scouts feeding implementers by artifact path.
- **Adversarial Review (arXiv:2608.18167):** a reviewer plus a critic of the review beat a five-agent baseline; the naive protocol fell into false consensus until disagreement had to be explicit and evidence-grounded. Basis for "findings are claims" and CONFIRMED/PLAUSIBLE labels, not for a standing critic role.
- **Anthropic, Patterns and problems in multiagent systems (2026-08-13):** 18 of 30 agents chose the same branch name; a fleet polling at 30 Hz issued 2.4M requests for 117 jobs. The lead assigns branch and worktree names; workers never poll.
- **Codex-session exercise (2026-09-09):** a successor silently adopted a checkpoint task id that did not match its brief, and model-reviewed auto-approval refused a status-file write. Source of the identity-mismatch rule and the `--approve-for-me` progress-file caveat.
- **Send-back cap (2026-09-10):** a terra `max` implementer was auto-resumed through four rejected reviews overnight (801k output tokens, 30% of that night's local Codex output) without the lead surfacing it. Basis for the default checkpoint at a second rejected review, which an explicit user or project agreement can supersede ([briefs and repairs](references/briefs-and-repairs.md#task-record-and-resume-check)).

## Context fuse evidence (added 2026-08-25)

Why the fuse is a semantic trigger plus the orchestrator's choice, not a token cap:

- **Anthropic (effective context engineering, 2025; long-running harnesses, Nov 2025 + Mar 2026):** compaction, note-taking and distilling sub-agents are the long-horizon tools; a fresh session with a structured handoff beat continued compaction on Sonnet 4.5 while Opus 4.5 ran fine on compaction, so reset policy is a judgment per model and workload. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents · https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Handoff Debt (arXiv:2606.02875) and Engram (arXiv:2603.21321):** context-bearing handoffs cut successor events 20–59% and prompt tokens 42–63% against cold takeover; a fresh successor with a distilled digest beats raw-history transfer.
- **Governance decay (arXiv:2606.22528):** policy violations went from 0% to ~30% on average (up to 59%) after compaction dropped the constraints; pinning them restored 0%. Hence respawn briefs restate the standing clauses, and worker auto-compaction is never trusted to keep them.
- **Cognition, multi-agents that work (Apr 2026):** clean-context reviewers beat context-sharing ones; single writer, helpers contribute intelligence. https://cognition.com/blog/multi-agents-working
- Confidence in the trigger policy is moderate; the architecture (external state, structured handoff, semantic triggers) is the high-confidence part.

## Claude harness fine print

Version-specific and rarely needed Claude-side mechanics; the hot-path rules stay in `SKILL.md` (Claude worker mechanics).

- **Resume and cache:** a per-invocation `model` sticks across `SendMessage` resume. Resume is cache-stable from 2.1.265 (2.1.267 for appended-system-prompt roles and forked background workers); a message delivered mid-run no longer drops a resumed worker's earlier thinking and prompt cache (2.1.290), so a mid-run steer costs no cache rebuild. Subagent transcripts: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`. An agent the user stopped (`x` in `/tasks`) refuses `SendMessage` with "agent was cancelled". A send to a name a newer agent took is refused, and the error names where the name now points; retarget by agent ID.
- **Cross-session messaging** is on by default: `SendMessage`/`ListAgents` reach independent sessions (background, `claude -p`, other terminals, cloud); plain text only. `notify_when_idle` hears a peer finish without polling. Delivery fine print: the Cross-session messaging section above.
- **Effort and roles:** `effort: low`→`max` in frontmatter overrides session effort on every model, and the Agent call's `effort` (2.1.292) overrides frontmatter and persists across resume (standing roles above); frontmatter is capped by any `maxEffortLevel` setting. `/tasks` names each subagent's model and effort. `--append-subagent-system-prompt-file` extends every role's prompt at launch. `experimental.cacheTtl: "1h"` in a role file keeps a long-lived role's prefix warm (session-wide: `subagentPromptCacheTtl`). `claude --agents '<json>'` at launch is session-scoped, immediate, and accepts `effort`. Headless `claude -p --agent <role>` ignores the role file's `effort:` (the Agent tool honors it); pass `--effort`.
- **Model resolution:** per-invocation `model` > frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` (a default, not an override) > inherit; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` makes the env var win. A *restricted* requested model warns and runs the parent model. `model: fable` roles honour a `[1m]` tag on `ANTHROPIC_DEFAULT_FABLE_MODEL`.
- **Output handling:** `TaskOutput` was removed in 2.1.277 and `taskOutputMaxChars` does nothing since; read a background task's output file with `Read`. A mid-stream cut auto-continues; a subagent that `SendMessage`-resumed another agent is woken by its completion. Background Bash commands stop at 30 min by default and 2 h at most only in unattended sessions (`-p`, Agent SDK, CI, cloud; 2.1.285, scoped 2.1.288), which kills a Codex worker mid-run: pass an explicit timeout on the launch or raise `BASH_DEFAULT_TIMEOUT_MS` / `BASH_MAX_TIMEOUT_MS`. Interactive sessions have no cap. `subagent_tokens` lands only at completion (a worker cannot count its own tokens — hence the semantic context fuse).
- **Worktrees:** `worktree.baseRef` accepts `"head"` only, not branch names — provision manually for a branch base. Commands that resolve to the main checkout fail inside a worktree.
- **Fan-out env:** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20; resumes take a slot); no lifetime cap. `--max-budget-usd` halts background subagents too. Background runs keep every MCP tool and only these built-ins: Read, Grep, Glob, LSP, Bash, PowerShell, Edit, Write, NotebookEdit, WebFetch, WebSearch, TodoWrite, Skill, ToolSearch, EnterWorktree, ExitWorktree, Monitor, TaskStop, SendMessage, Artifact (Agent and ExitPlanMode follow their own rules). MCP calls over 2 minutes auto-background. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces every subagent foreground. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` hot-disables the teammate naming trap. `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` (2.1.296) runs every Workflow agent on one model while other subagents keep theirs.
- **Headless and forks:** `subagent_type: "fork"` inherits your full conversation and prompt cache, always runs on your model, and is exempt from the depth cap. `claude -p --bare` is the headless worker for scripts/CI only (a `cd` persists across stream-json turns). Since 2.1.292 a one-shot `claude -p` waits for its background commands and scheduled wakeups after the final result instead of stopping them, and since 2.1.295 it names what it is waiting for on stderr; a wrapper timeout must allow for that tail. `-p`/SDK forking needs `CLAUDE_CODE_FORK_SUBAGENT=1`. `/fork` spawns an independent background session (keeps the parent cache; git behavior and control as in background sessions); `/subtask` is the in-session variant.

## Codex flag fine print

The `exec` flag surface is byte-identical from 0.155.1 to 0.162.1 (`codex-rs/exec/src/cli.rs`) apart from `--cyber-access-program` (0.161.0, unused), the JSONL event schema and processor are byte-identical from 0.160.0 to 0.162.1, and the dispatch helper's flags were checked against 0.162.1's help. The helper uses none of `--worktree` (watch items), `--ignore-rules`, `--thread-source` or `--dangerously-bypass-hook-trust`. `--enable/--disable <feature>` equals `-c features.<name>`. `-p <name>` layers `$CODEX_HOME/<name>.config.toml`; a profile could replace the pins, but codex hard-errors while legacy `[profiles.*]` tables remain in `config.toml`, so the helper pins flags and ignores the user's config. Events files carry `web_search` items; `.aws` directories under writable roots stay protected, and explicit filesystem denials hold on approved commands.

Standard starts/resumes/forks use [the dispatch helper and run record](references/runtime.md#dispatch-from-one-record). It pins model/effort/cwd and separates artifacts; it does not select a tier or widen the chosen permissions. A 2026-09-11 session audit found two omitted-flag resumes despite the written rule, so these settings are required input rather than inherited intent. Actual runtime settings still require observed evidence.

- `--strict-config` errors on unrecognized keys — pair it with the pins. `codex doctor --json` reports the resolved `model` and version at zero tokens (batch preflight). The planning tool is off by default (`tools.update_plan.enabled = true` restores), so JSONL carries no plan items.
- `--ephemeral` skips session files (forfeits resume — fails loudly); `--add-dir <dir>` grants extra writable roots beyond `--cd`; `-i <file>` attaches images on dispatch and resume.
- `resume --last` is cwd-filtered (`--all` lifts it); exec-spawned threads only have UUIDs; "restore working directory" is TUI-only; resume emits a warning error item when the model resets to the config default, and only the *permission profile* is restored.
- `review --title` needs `--commit` only when used alone. Top-level `codex review` lacks `-m` and `--json`: pin the model with `-c model="..."`, or use `codex exec review`.
- Manual `exec resume` / `exec fork` (outside the helper) runs in the invoking cwd and rejects `--cd`/`-C` and `-s`; pin sandbox through config and keep every other helper flag. No `exec --full-auto`; use `-s workspace-write`. `--search` is TUI-only; exec web search is `-c web_search="live"`.
- JSONL `item.*` events carry `command_execution` (`command`, `exit_code`, `aggregated_output`, `status` `completed`/`failed`), `file_change` (`changes[]` of absolute `path` and `kind`), `web_search`, `agent_message`, `reasoning`; a run ends `turn.completed` or `turn.failed`. A turn interrupted by SIGINT makes `exec` exit 1 within about two seconds and writes no closing event and no `--output-last-message` file; the rollout records `turn_aborted` (reason `interrupted`), the running command dies with the process, and `exec resume` on the thread works, with the model told the turn was interrupted (live, 0.160.0, `AUDIT.md` 2026-10-03). The handler is registered only after the session is configured (`exec/src/lib.rs`).
- Effort scale: `minimal` is pre-5.6 legacy; `ultra` is ChatGPT-auth only (the API rejects it); `persistent` is a binary enum outside the catalog. Catalog defaults drift without a CLI update: `~/.codex/models_cache.json` is etag-refreshed from the server and sets the bare default (gpt-6.1-sol at `low` since 0.159.1; `codex doctor --json` shows it), which is why `-m` and `-c model_reasoning_effort` are always passed.
- Dispatch chains: join with `;` not `&&` after `git commit` — a no-op commit exits non-zero and kills the chain.
- `browser_use` / `computer_use` / `image_generation` feature flags are stable and enabled; verify on first headless use.
