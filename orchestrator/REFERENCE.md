## Fast mode

Fast mode needs **both** `-c service_tier=fast` **and** `--enable fast_mode`, is ChatGPT-auth only, and burns credits at 2.5× (measured on the prior generation; docs 2026-09-30: 2.5× included usage, 2× purchased credits; Astra Ultrafast 8× / 6×). No catalog entry sets a default service tier (server catalog checked 2026-09-30), so an exec dispatch without `-c service_tier` bills Standard. API side: Fast mode replaced Priority Processing 2026-07-30 — sol only, 2× price for up to 2.5× speed — irrelevant for background workers, whose latency the orchestrator absorbs.

## Profiles vs pinned flags

The dispatch template pins flags explicitly so the skill is self-contained regardless of `~/.codex/config.toml`. Profiles — `-p <name>` layering `~/.codex/<name>.config.toml` — can replace the pins, but codex hard-errors if legacy `[profiles.*]` tables remain in `config.toml`; explicit flags are more portable.

## Reaching GPT models from inside Workflow scripts

Workflow scripts' `model:`/`agentType:` params only take Claude values. Reach astra or gpt-5.6 by wrapping: spawn a cheap Claude agent (`model: 'sonnet'`, `effort: 'low'`) instructed to compose the self-contained spec, run `codex exec` per `SKILL.md`, verify, and return the last-message file's content verbatim. A Workflow resume whose run journal is missing fails with a clear error; in auto mode, `agent()` calls with large output schemas go through the classifier.

## codex mcp-server (deprecated 2026-08-24)

`codex mcp-server` (the `codex`/`codex-reply` MCP tools) is deprecated: OpenAI's Codex changelog (2026-08-24) and the docs page say to use the Codex app server, or `codex-plugin-cc` from inside Claude Code, instead. 0.153.4 still ships the subcommand with no deprecation notice in `--help`. No loss for this skill — background `codex exec` keeps the kill/steer control it relies on; build no new wiring on it.

## Native Codex multi-agent (v2 stable as of 0.145.0)

Codex can spawn its own sub-agent threads; settings unified under `[agents]` in config.toml (verified against 0.145.0 source: `enabled` default true, an enabled `features.multi_agent_v2` takes precedence; `max_concurrent_threads_per_session` alias `max_threads`; `default_subagent_model` / `default_subagent_reasoning_effort`; per-role `[agents.<role>]` tables; `max_depth` is V1-only). This skill deliberately doesn't orchestrate through it — separate dispatches keep per-worker kill/steer, and that's structural, not preference: V2 subagents live behind parent-owned mailboxes, and the app-server *rejects* external input to a spawned child (openai/codex#27173) — an outside orchestrator physically cannot steer inside a worker's fan-out. A worker fanning out internally is fine; you verify the final diff. `spawn_agents_on_csv` was **removed** in 0.145.0 (#34413; `job_max_runtime_seconds` survives as a config no-op) — official docs still describe it, ignore them. As of 2026-08-13 the docs match the `[agents]` keys and ship three built-in roles (`default`, `worker`, `explorer`); MAv2 delegation policy is `none` / `explicitRequestOnly` (new-thread default) / `proactive`, with `ultra` as the documented proactive trigger (SKILL.md Notes). "Leaf model" work (#36892) points at per-subagent model assignment — the steering objection stands; re-evaluate on next audit. (0.146.0: agent-plugin manifests + marketplaces, incl. a Claude Code-format one — changes nothing about dispatch mechanics.) The 0.159.2 catalog gives gpt-6.1-sol `multi_agent_version: v2` with `multi_agent_reasoning_effort: xhigh` (5.6 and gpt-reserve stay v1): a 6.1-sol lane lead's spawned subagents run at `xhigh` whatever the parent's effort, which is the cost to model in the lane-lead A/B.

## Standing roles (portability bootstrap)

SKILL.md routes to standing roles in `~/.claude/agents/`. The role files ship in this skill's `agents/` folder — install with `cp agents/*.md ~/.claude/agents/`, then dispatch **next turn** (a new role file registers only at the turn boundary; so do edits: on 2026-09-24 a same-turn dispatch of an edited role ran its old body). On an update, compare shipped and installed copies, preserve unrelated local changes, and sync only the changed roles; editing `agents/` alone does not update the installed copies. A running session may retain previously loaded instructions, so do not assume an edit was applied to work already in flight. Roles exist because effort is frontmatter-only; the baked-in contracts are convenience. (Project roles live in that project's `.claude/agents/` and are not shipped here.)

Shipped roles and what differs between siblings: `scout-high` (sonnet/high, read-only tools plus an exact-name allowlist of Linear, Google Drive, and Claude Docs read tools; server-level `mcp__<server>` patterns would also grant their write tools; was `scout-low` at sonnet/low until 2026-09-22); `implementer-opus-med` / `-opus-xhigh` (one body, `effort` and the tier words in `description` differ; `implementer-sonnet-high` and `implementer-opus-low` retired 2026-09-22, `implementer-opus-high` retired 2026-09-25 — delete an installed copy if one survives); `pr-reviewer-med` / `-xhigh` / `-max` (one body, `effort` and the routing clause in `description` differ; `-max` carries the user-gated clause; `pr-reviewer-high` retired 2026-09-26, when `-med` became the default and `-xhigh` the retry — delete an installed copy if one survives); `researcher-opus-med` / `-opus-high` (one body, `effort` and the routing clause in `description` differ; read-only, no Write tool, reports via Bash to the brief-named path, preload frontier-search); `docs-sync-sonnet-high` (sonnet/high, all tools except `Agent` and `NotebookEdit`, edits only brief-named doc paths). Frontmatter surface used: `name`, `description`, `model`, `effort`, `tools`, `disallowedTools`, `skills`, `hooks`.

Role bodies (2026-09-24) separate **fixed rules**, which a brief can't relax, from **defaults**, which the brief overrides: scope, method, source window, return shape, report path. Every body also says CLAUDE.md's approval, planning, and PR-landing rules belong to the lead. The read-only roles (scout, researcher, reviewer) run `~/.claude/hooks/role-guard.py` as a frontmatter `PreToolUse(Bash)` hook. It denies git and GitHub mutations. Quoted text, comments, and heredoc bodies never trip it, though a `$(...)` in an unquoted heredoc runs and is judged. It unwraps wrappers, `sh -c` and `rtk run` strings, `eval`, scripts (run by a shell, sourced, executed by path, or piped in), and user aliases, and it judges curl, wget, and HTTPie writes to the GitHub API. It allows `--help`, supported `--dry-run` forms, a detached worktree under a temp folder (the reviewer's way to run code at the reviewed commit), and writes inside a throwaway repo whose git dir is under a temp folder. A `cd` into such a repo counts only when it certainly ran (through `&&`, or to a directory that exists or was just made); otherwise the write is denied with a hint to join `cd` to git with `&&`. Pushes from a throwaway repo may go only to another throwaway repo under a temp folder. Each deny message names the read-only alternative before the `ESCALATE` instruction. Fixtures are in `test_role_guard.py`, run with `python3 test_role_guard.py` in that folder. To check a guard change against real traffic, run `replay_role_guard.py`, which replays past read-only subagent Bash calls from `~/.claude/projects`. After an adversarial review on 2026-09-24 it replayed 10,725 calls and the guard denied 15: seven correct, two scripts built with `sed` and run in the same command (denied by design), five whose worktree, branch, or scratchpad no longer exists, and one cautious `git add` after a `cd` it couldn't pin to one directory. Neither hook ships with this skill. The command ends in `|| true`, so on a machine without them the roles run with only their text rules. In a live probe (2026-09-24), a scout asked by a brief to commit attempted the commit and the hook blocked it, so the hook is what enforces the floor. Claude Code also injects a subagent note: "Do NOT Write report/summary/findings/analysis .md files … the parent agent reads your text output". Every role that writes a report says this note doesn't cover its report, because the lead reads that file.

## Cross-session messaging fine print

Windows support landed 2.1.241. Loops self-terminate (rate-limit, dedupe, 50/100 caps). The hold-then-drop path: an unset-`crossSessionInbound` bypass receiver *holds* messages from non-bypass senders, then drops after `dialogExpiry` (default 5 min); interactive sessions set accept/hold/refuse and expiry via `/config`. Since 2.1.238 a `refuse` receiver and rate-limit/full-inbox drops report back to the sender — hold-then-expire is the only path still failing silently. `SendMessage` delivers to a bare name matching one live session (`name-word-word` variants on collision); oversized and rapid-burst messages are refused up front.

Same-machine delivery rides a per-session unix socket (`/status` → `Peer address`); each session exports `CLAUDE_CODE_MESSAGING_SOCKET`/`_TOKEN` to hooks and Bash, so a script can post into its own session — a push upgrade over polling progress files (first auth line: `{"type":"auth","token":...}`). Cross-machine and cloud routes go through Anthropic servers via Remote Control; containers can't reach host sessions. `dialogExpiry: "never"` keeps default-held messages until session end. Agent-team teammates are a separate roster, never listed by `ListAgents`; structured team protocol messages stay within the team.

## Agent teams mechanics

(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`): peer Claude sessions with a shared dependency-tracked task list, inter-agent messaging, plan-approval gates, and quality hooks (`TeammateIdle`, `TaskCreated`, `TaskCompleted` — exit 2 sends feedback and keeps the teammate working). Enabled in user settings 2026-08-02. Verified against docs/changelog: since v2.1.178 every session is one implicit team — spawn teammates via the Agent tool's `name` param, message by name (`team_name` ignored; `TeamCreate`/`TeamDelete` removed — guides describing them are stale). Subagent definitions double as teammate roles (`tools`/`model` honored; `skills`/`mcpServers` ignored). Since v2.1.234 teammates inherit the lead's model and effort unless the spawn names one or `CLAUDE_CODE_SUBAGENT_MODEL` is set. Since 2.1.265 teammates and resumed subagents keep SubagentStart hook context and preloaded skills inside the cached prefix on later turns (a cache-miss class before). **Naming trap:** any named Agent spawn launches as a teammate — even self-named during ordinary delegation. Its final answer rides in the idle notification, but it is still a teammate (no auto worktree, team-lifecycle semantics, top cost surface); set the env var to `0` (hot-applied) to get named subagents back. Display default is `in-process` since v2.1.179; split panes need tmux or iTerm2+`it2` (not VS Code terminal/Windows Terminal/Ghostty). Cost: official estimate ~7× a standard session with plan-mode teammates — Sonnet teammates, 3-5 of them, ~5-6 tasks each, shut down when done. Limits: no `/resume`/`/rewind` of in-process teammates (lead may message dead teammates after resume), no nested teams, no background subagents from an in-process teammate, task-status can lag, one lead/team per session, no automatic worktree isolation — partition by file ownership; task-claim locks don't guard file edits. On disk (docs 2026-08-13): mailboxes `~/.claude/teams/{team}/inboxes/{agent}.json`, roster `~/.claude/teams/{team}/config.json` (teammates can read it to discover peers — brief them to), tasks `~/.claude/tasks/{team}/` — the task list survives resume; in-process teammates don't. Teammates never appear in `ListAgents`: team roster and cross-session messaging are separate namespaces sharing one `SendMessage` tool (cross-session is plain text only). Org kill switch: managed settings denying `SendMessage`/`ListAgents` also remove subagent and teammate messaging — SendMessage-resume can be silently disarmed in a managed org.

## Review and repair evidence (added 2026-09-09)

Why send-backs carry a diagnosed defect, why reviewers get artifacts rather than transcripts, and why the repair count follows the task:

- **Repair or Resample? (arXiv:2608.25920, 2026-08-26):** 536 annotated multi-agent failure trajectories; unguided reruns reproduced 67.97% of failures and repaired 6.90%, symptom-driven intervention repaired 20.15%. A re-dispatch without a diagnosed defect is a resample, not a repair — the directing table's send-back row and the per-task repair count rest on this.
- **The Interaction Tax (ICML 2026, arXiv:2608.23541, 2026-08-24):** when agents read each other's complete outputs, proposals converge within one round; "multi-agent performance depends less on the number of agents than on the information they exchange." Reviewers get the diff and the author's report as leads, never the author's verdict or transcript; scouts feed implementers by artifact path.
- **Adversarial Review (arXiv:2608.18167, 2026-08-16):** a reviewer plus a critic that audits the review beat a five-agent baseline on LiveCodeBench with three agents; the naive protocol hit a false-consensus mode on SWE-PRBench until the prompt demanded explicit, evidence-grounded disagreement. Evidence for "findings are claims, not verdicts" and CONFIRMED/PLAUSIBLE labelling — not, on its own, grounds for a standing critic role.
- **Anthropic, Patterns and problems in multiagent systems (2026-08-13):** 18 of 30 agents chose the identical branch name; a job-queue fleet polling at 30 Hz issued 2.4M requests and accepted 117 jobs. The lead assigns branch and worktree names; workers never poll.
- **Codex-session exercise (2026-09-09, validation report kept locally):** a successor worker silently adopted a checkpoint's task id that did not match its brief; a status-file write was refused under model-reviewed auto-approval and a read-only CHECKPOINT turn was the working fallback. Unverified lead from the same pass: a Feb 2026 paper on consensus-over-expertise losses (up to 37.6%) surfaced only in a search snippet.

- **Send-back cap (2026-09-10, local overnight Codex usage report):** a terra `max` implementer on a project task was auto-resumed through eight turns and four rejected review checkpoints, 10:44 p.m. to 7:01 a.m., 1,399 responses and 801k output tokens (30% of all local Codex output that night). ## Context fuse evidence (added 2026-08-25)

Why the fuse is semantic-trigger + orchestrator-choice, not a token cap:

- **Anthropic, effective context engineering (2025):** three long-horizon tools — compaction (preserve decisions/unresolved bugs, drop stale tool output), structured note-taking (artifact survives context resets), sub-agents (explore on tens of thousands of tokens, return 1–2k distilled). Choose by task shape. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **Anthropic, long-running harnesses (Nov 2025 + Mar 2026 follow-up, via cross-model sweep):** compaction alone insufficient; structured handoff + fresh session beat continued compaction on Sonnet 4.5 ("context anxiety"), while Opus 4.5 ran fine on continuous compaction — reset policy is model/workload-dependent: an orchestrator judgment, not architecture. https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Handoff Debt (arXiv:2606.02875):** 181 takeover tasks — context-bearing handoffs cut successor agent events 20–59% and prompt tokens 42–63% vs cold takeover; structured/summary notes beat raw traces. Respawn-from-artifact is cheap when the artifact is good.
- **Governance decay (arXiv:2606.22528):** 1,323 episodes, 7 model families — 0% policy violations with constraints in context, ~30% avg (up to 59%) after compaction dropped them; constraint pinning restores 0%. This is why respawn briefs restate the standing clauses and why worker auto-compaction is never trusted to preserve them.
- **Engram (arXiv:2603.21321):** fresh successors with empty context + persistent digest/archive outperform both raw-history transfer and no-handoff; the distilled digest matters more than the raw archive.
- **Cognition, multi-agents that work (Apr 2026):** clean-context reviewers beat context-sharing ones ("context rot"; avg 2 bugs/PR caught); single-writer + intelligence-contributing helpers. https://cognition.com/blog/multi-agents-working
- **Convergent synthesis (both research tracks):** compact within a coherent phase; respawn at phase boundaries, on drift, or for independent review; summaries are navigation aids while artifacts/files stay the authority (Manus: drop content only with a restorable handle). Trigger-policy confidence is moderate — model- and workload-dependent; the architecture (external state + structured handoff + semantic triggers) is the high-confidence part.

## Claude harness fine print (moved from SKILL.md 2026-09-10)

Version-specific and rarely needed Claude-side mechanics; the hot-path rules stay in `SKILL.md` (Claude worker mechanics).

- **Resume and cache:** a per-invocation `model` sticks across `SendMessage` resume. Resume is cache-stable from 2.1.265 (2.1.267 for appended-system-prompt roles and forked background workers; earlier builds re-rendered the prompt prefix on resume). Subagent transcripts: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`.
- **Cross-session messaging** is on by default: `SendMessage`/`ListAgents` reach independent sessions (background, `claude -p`, other terminals, cloud); plain text only. `notify_when_idle` hears a peer finish without polling. Delivery fine print: the Cross-session messaging section above.
- **Effort and roles:** `effort: low`→`max` in frontmatter overrides session effort on every model; capped by any `maxEffortLevel` setting. `--append-subagent-system-prompt-file` extends every role's prompt at launch. `experimental.cacheTtl: "1h"` in a role file keeps a long-lived role's prefix warm (session-wide: `subagentPromptCacheTtl`). `claude --agents '<json>'` at launch is session-scoped, immediate, and accepts `effort`. Project roles live in the project's `.claude/agents/`.
- **Model resolution:** per-invocation `model` > frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` (a default, not an override) > inherit; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` makes the env var win. A *restricted* requested model warns and runs the parent model. `model: fable` roles honour a `[1m]` tag on `ANTHROPIC_DEFAULT_FABLE_MODEL`.
- **Output handling:** `taskOutputMaxChars` (≤128K) sets how much task output arrives inline before spilling to a file (disk copy capped at 1 GB) — raise it for large-diff legs. A mid-stream cut auto-continues; a subagent that `SendMessage`-resumed another agent is woken by its completion; subagent-started background commands have no one-hour cap. `subagent_tokens` lands only at completion (a worker cannot count its own tokens — hence the semantic context fuse).
- **Worktrees:** `worktree.baseRef` accepts `"head"` only, not branch names — provision manually for a branch base. Commands that resolve to the main checkout fail inside a worktree.
- **Fan-out env:** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20); no lifetime cap. MCP calls over 2 minutes auto-background. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces every subagent foreground. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` hot-disables the teammate naming trap.
- **Headless and forks:** `claude -p --bare` for scripts/CI (a `cd` persists across stream-json turns since 2.1.265; an exact-id `-p --resume` failed once unexplained on 2.1.266 — seed a fresh `-p` from the artifact rather than debug it, see watch items). `-p`/SDK forking needs `CLAUDE_CODE_FORK_SUBAGENT=1`. `/fork` spawns an independent background session (keeps the parent cache; managed by `claude attach/logs/stop/respawn`; idle-timeout race fixed 2.1.265); `/subtask` is the in-session variant. A `/fork`/`claude agents` session that changed code commits and pushes before finishing.
