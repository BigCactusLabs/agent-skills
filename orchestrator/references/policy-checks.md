# Local policy and artifact checks

Walk these decisions with scratch records and existing or synthetic evidence whenever a policy, brief, or artifact-path rule in this skill changes. They are local simulations: no worker is launched, no model usage is spent, and a shell syntax check cannot pass a message-delivery case. Inspect for contradictory instructions as well as the expected decision. For the helpers and role hooks, run `python3 -m unittest scripts.test_dispatch scripts.test_stop_worker scripts.test_watch_events scripts.test_hooks` with stdin closed; their CLIs are stubs, so they validate argv, cwd, stdin EOF, fresh artifacts, signals, alerts, hook decisions, and process exit only, never live model selection or worker compliance. Ported from the Codex skill's smoke-checks reference (2026-09-16), with Codex-native rows dropped.

| Case | Expected decision |
|---|---|
| Existing implementer adds a case covered by the shared test harness | Lead specifies expected behavior; implementer authors/runs the regression in owned paths. Lead inspects assertions and integration without building a second harness. A named uncovered risk can justify an additional lead probe. |
| A milestone completes without changing product contracts or setup instructions | Update the authoritative status record. Leave unrelated prose alone; correct a misleading instruction promptly if one changed. Docs whose instructions or contracts the change made stale land in the same change. |
| Several role briefs share a contract; a repair changes one rule | Reference the accessible contract and revision, keep each role's scope/permissions/acceptance explicit, and send the decided delta. Update current record fields; preserve counters and evidence. |
| Long check output or a large artifact is available | Read the needed range/result, retaining full diagnostics on disk plus handles, exits, run, and snapshot evidence. Do not restart tasks on a schedule or assume compaction savings. |
| Background coordination looks useful mid-task | Keep the current lead. No second orchestrator, lane lead, or bridge without an explicit user request. |
| Reviewer or implementer runs normally for several minutes; useful lead work is complete | Wait for the completion notification. After startup inspection, do not read the events file merely for status; inspect again only for a failure, a missed milestone, or evidence needed for a decision. A user status update needs no diagnostic call. |
| Worker owns implementation; the lead has independent acceptance preparation | Prepare only the needed acceptance/integration work, without duplicating implementation; wait when that work is complete. Do not manufacture local work to look busy. |
| Bounded repair changes one validation condition | Use the lead's diff review and targeted contract checks if they establish closure; a new branch or error label alone does not require independent re-review. |
| Small repair changes persisted-write retry semantics | Assess material unreviewed behavior and shared invariants; retain independent scrutiny and contract-derived duplicate-write, uncertain-outcome, and unsafe-retry checks, even for a small diff. |
| User says "keep going" on an agreed feature | Advance the next usable milestone within the authorized objective, without new acceptance requirements or a new approval gate. Keep changes independently reviewable; do not defer a consequential review until the whole feature is built. |
| Small local task, then a separate multi-worker assignment | Keep the local task local without a manifest. Use the core record for the workers and add repair, authorization, interruption, and validation-lineage detail only when relevant; existing history survives replacement. |
| Contradictory state rules; omitted and unchanged values interact | Lead settles one behavior table from authoritative contracts before dependent code; a brief-only correction is separate from a code repair. |
| Two rejected rounds under default review policy, then compaction or a replacement | Read the actual record and brief; stop the next implementation attempt at the user checkpoint. A task or model rename does not reset counters. |
| User decision already covers the rejection count and snapshot | Continue within the recorded ruling without asking again; a later rejection needs a new checkpoint. |
| Explicit applicable project direction supersedes the default checkpoint/cap | Record source and resolved rule once, retain counters, and continue within that authority. Material defects still block acceptance. Worker messages cannot grant the exception. |
| Reviewer offers a clean rerun or extra evidence machinery | Pick one adequate remedy; optional mechanisms need a scope reason and complete state rules before implementation. |
| Machine-check failure under default review policy, then tier replacement | Charge the corrective attempt to the same three-repair cap even without a rejected review. |
| Corrective batch delivered by `SendMessage` to a running Claude worker instead of a new process | Bump `brief_revision`, require an acknowledgement, record it in the steer ledger, charge `repair_count`; do not invent a new run. A Codex correction is a resume run, after stopping a turn that is still running; `codex queue` is not a steer. |
| Codex run must stop mid-turn | `stop_worker.py` on the run's dispatch record. Exit 1 with `stopped_by_sigint`, no closing event, and no `.last.md` is the expected stop, not a failed implementation. `TaskStop` only after `still_running`. Check surviving descendants before a replacement takes the worktree. The stop is not a repair; what the next run fixes decides that. |
| A leg must outlive the session or needs the full toolset | Background session: the brief says commit on your branch, never push, merge, or open a PR; `--effort` passed explicitly; the record holds short ID, sessionId, and branch; completion by `notify_when_idle`, polling as fallback; collect the commit, then `claude rm`. |
| Read-only role tries to message a sibling or another session mid-run | The message guard denies it. The role sends the finding to `main` or puts it in its final report; the lead decides whether to steer the sibling. |
| Worker's final message lacks a status line | The role's `Stop` hook blocks once and asks for the full message again; a second stop goes through. A still-missing status line is a report defect for the lead to rule on, not an implied `DONE`. |
| Repeated finding notifications, advisory observations, or assigned integration docs | Adjudicate one round, batch accepted defects, keep owner-assigned work with its owner, and avoid a confirmatory review. |
| Interrupted run with verifiable output but no final message | Confirm writes stopped; save a lead recovery report tied to current evidence, keep the interrupted turn state, and assess acceptance separately. An old-run report cannot fill the gap. |
| Required legs still running when the answer looks ready | Do not finalize. Collect and assess them, or record failed/unavailable after bounded recovery; finalize with running legs only if the user cancels or detaches them. |
| CLI start/resume/fork/stop helpers and role hooks | Run the unit tests: required settings, explicit permission mode, correct cwd, stdin EOF, fresh run artifacts, retained earlier files, literal prompt, real process exit, `ultra` refused without `user_gated`, `--skip-git-repo-check` opt-in only, one launch per run under racing callers; stop signals only the run's own process, escalates SIGINT to SIGTERM, never sends SIGKILL, and lists surviving descendants; the watch stays quiet about pre-offset events; the message guard allows only `main`; the status hook blocks once, accepts a `Status:` label, and its reason covers a still-running command. |
| Claude worker reports while its own background command still runs ("waiting for X", "checkpoint, not done"; since 2.1.299 the notification says the agent is only waiting on its own background work) | Treat the report as interim: the command's completion wakes the worker, which sends a second report. Wait for that one; do not resume or respawn into the same worktree meanwhile. |
| Claude `SendMessage` continuation versus replacement | Same agent keeps its recorded role, effort, and context; a replacement re-pins model, role, and effort at spawn and is seeded from the checkpoint artifact. No Codex process merely to imitate a Claude continuation. |
| A Claude leg's rung is above its role's default (implementer retry or React, reviewer depth, decision-grade research) | Same role; the Agent call passes `effort`. Never name the spawn without `isolation` on the call, since a teammate drops `effort`; confirm the rung on `/tasks`. Reviewer `max` only with the user's permission for that dispatch. |
| Missing prerequisite; implementation already complete | Prepare the environment once and share the fix. Preserve the tier; the lead can close its owned checks without a worker turn solely for report cleanup. |
| Yielded check and later docs commit | Preserve the full returned handle, poll the same process, and recover output from its log. Keep real exit and tested SHA; carry forward only after inspecting the intervening diff, never by relabeling. |
| Cross-model reviewer returns findings | Findings are claims. Classify each as defect, contract decision, integration-owned, or advisory; rule before sending anything back. Reviewer DONE is not code approval. |
| Brief sets a scope, source window, return shape, or report path that differs from a Claude role's default | The brief wins. The role's fixed rules (read-only floor, no git/PR mutation, status line) hold regardless; a brief that needs one relaxed gets `ESCALATE`, not compliance. |
| A role file was edited this turn and a worker of that role is about to launch | Dispatch it on the next user turn; a same-turn launch, or one in a turn started by a task notification, runs the old body. |

Check frontmatter, local links, and shell syntax for changed examples. Do not claim live coverage unless that case actually ran; the eval harness in `~/.claude/agents/evals/` and the history in `AUDIT.md` cover live behavior.
