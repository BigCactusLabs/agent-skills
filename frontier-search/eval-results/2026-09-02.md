## 0. Environment confounds — read before the verdicts

1. **Shared search cap.** All 23 agents ran in parallel inside one session and shared the 200-call WebSearch cap. Nine runs hit it mid-loop (E1-opus, E2, E6-opus, E8, E10, E11, E12, E13, E16-opus). Every one of them reported it as `Capped:` rather than as a thin topic, which is itself a pass of the Runtime-facts rule, but later rounds in those runs were fetch-only. Run future suites in batches of ≤6 or in separate sessions.
2. **Codex quota exhausted.** Every cross-model sweep (E1-opus, E2, E6-opus, E9-opus, E10, E11, E13, E16-opus) died on "You've hit your usage limit... try again at Sep 6th, 2026" or on MCP transport errors. The E10 diff step (agreement / sweep-only / disagreement) is therefore untested. Check `codex` quota before the next run.
3. **Stale sweep file collision.** A `codex-sweep.md` from the earlier upgrade session sat in the shared scratchpad. Four runs found it at their sweep output path and rejected it by timestamp and topic. Correct behaviour, but the SKILL.md example command should use a unique output path per run.
4. **Message truncation.** Subagent results over 16K characters were dropped by the channel; all were recovered by having agents write to files. Raw outputs: `scratchpad/evals/raw/*.md` (session-local, not kept in the skill dir).
