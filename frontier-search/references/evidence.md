## Runtime facts

Verified 2026-09-22 and re-verified 2026-09-30 (Claude Code 2.1.285) against https://code.claude.com/docs/en/tools-reference and https://code.claude.com/docs/en/changelog, both fetched as raw markdown via `curl` (`<page>.md`) — the tools page exceeds WebFetch's truncation limit, and on 2026-09-30 WebFetch's extraction of the changelog assigned a 2.1.285 entry to 2.1.284, which the raw file corrected.

- Session cap: 200 WebSearch calls per session, counted across the main conversation and every subagent; requires v2.1.212+; raised (never disabled) with `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`; `/clear` resets the count unless a running workflow survives the clear. A capped call appears as a search that did nothing; the notice tells Claude to continue with what it has and to ask the user to raise the limit if more are needed.
- WebSearch may issue up to eight backend searches per call; `allowed_domains` and `blocked_domains` cannot be combined in one call; US-only per the tool's own description.
- WebFetch truncates large pages to a fixed character limit before extraction; the docs recommend `curl` via Bash for the raw page. Cache is 15 minutes by default (`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`, v2.1.233+). Five-minute download deadline (`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`, v2.1.268+, `0` removes it). Cross-host redirects returned, not followed. Refuses hostnames without a dot.
- Cloud (Cowork) sessions carry a separate fetch budget; since v2.1.278 (2026-09-19) a refused fetch says why.
- claude.ai artifact links are read with the Artifact tool, not WebFetch (v2.1.271).
- Domain safety check (https://code.claude.com/docs/en/data-usage#webfetch-domain-safety-check): before fetching, WebFetch sends only the hostname to `api.anthropic.com` for a blocklist check; a passing host is cached five minutes; runs on every provider; `skipWebFetchPreflight: true` disables it. v2.1.285 fixed a rate-limited check being reported as a network or enterprise policy block.
- Availability: v2.1.285 added `CLAUDE_CODE_DISABLE_WEB_FETCH` and made Team/Enterprise sessions (and sessions with an undetermined plan) withhold WebFetch until organization policy loads when it could not load at startup. WebSearch is available on the Claude API and Claude Platform on AWS, on Foundry only for Anthropic-hosted deployments, on Google Cloud's Agent Platform for Claude 4+; Amazon Bedrock does not expose it. v2.1.282 fixed web search not being offered on Vertex AI for models Claude Code did not yet recognize.
- WebFetch sends a `User-Agent` beginning with `Claude-User` and an `Accept` header preferring Markdown. v2.1.281 keeps web search results that already arrived when a proxy drops a stream event. v2.1.283 adds WebFetch/WebSearch outputs to the `tool.output` OpenTelemetry span only when `OTEL_LOG_TOOL_CONTENT=1`.
- Claude Code bundles a `/deep-research` workflow (fans out searches across subagents, cross-checks, writes a cited report). Since v2.1.218 it runs only when the user invokes it (https://code.claude.com/docs/en/commands).
